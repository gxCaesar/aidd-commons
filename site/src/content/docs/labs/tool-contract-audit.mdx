## Preparation and learning objectives

Read [Retrieval, tools and feedback](/learn/scientific-agents/retrieval-tools-feedback/) first. This laboratory audits the project's own laboratory returns. You will check a return record against 6 declared obligations, identify the field behind each refusal, and distinguish a self-describing artefact from a verified measurement. Familiarity with JSON helps.

The mode is fresh independent computation over a frozen protocol and committed local return records. Use the project Python 3.11 environment and CPU. No network, download or accelerator is needed. The `download` command verifies the local material and writes nothing. The inspection commands write nothing. The exporter overwrites only the compact summary after its checks pass.

```bash
.venv/bin/python labs/tool_contract_audit/run_lab.py download
.venv/bin/python labs/tool_contract_audit/inspect_tool_contract_audit.py show
.venv/bin/python labs/tool_contract_audit/inspect_tool_contract_audit.py check
.venv/bin/python labs/tool_contract_audit/export_summary.py
.venv/bin/python -m pytest labs/tests/tool_contract_audit -q
```

## Return-record contract

Each counted unit is one laboratory return record. The audit covers every laboratory with a committed return record except this audit. Its own return record is the file the audit writes, so the frozen protocol excludes it from the input set. The protocol also names the companion files. The checker returns all failed fields for each record. Missing fields and present fields with empty or invalid values receive different reasons. Laboratory-specific result fields are allowed.

| Contract part | Declared rule |
| --- | --- |
| Schema | Require `schema_version`, `protocol_id`, `computed_on`, `software`, `environment`, `side_effects`, `outcome_status` and `scientific_meaning` with declared types. The first 4 are shared by every observed return. The remaining fields make the full return contract explicit. |
| Version | Nonempty `schema_version` and `protocol_id` identify a versioned artefact. Without either, the return cannot be read as one. |
| Environment | Require `software.python`, nonempty `environment.requires` and `environment.unavailable`, and `environment.can_attest_external_execution` set to false. A return cannot attest where a process actually ran. |
| Side effects | Require `side_effects.allowed_writes` as a list of repository-relative paths. An empty list declares no allowed writes and makes that claim checkable against a separate trace. |
| Error states | `outcome_status` is `complete`, `no_result` or `halt`. `no_result` licenses no usable result. `halt` also requires stopping. The source laboratories have no uniform top-level error field, so missing status is not read as success. |
| Scientific meaning | Require nonempty `scientific_meaning.licenses` and `scientific_meaning.does_not_license`. The audit separately counts existing explicit limit fields without treating them as a complete meaning statement. |

## Independent check

Compare `applicability_domain_audit` with `assay_endpoint_controls` in `show`. The former declares a `does_not_do` limit and the latter has no field in the limit search. Both still fail the full contract on E, S, R and M. An explicit limit is useful, but it does not supply an execution status or a write declaration.

## Limits of the material

This laboratory audits a contract, not a measurement. A passing return says that the artefact is self-describing and nothing more. The audit cannot establish that the laboratory measured anything true, that the tool ran where the return says it ran, or that a reader can reproduce the result from the return alone. A declared environment or allowed write is not an independent process trace. The verdicts do not rank the laboratories or measure their scientific quality. No reader learning outcome was observed.
