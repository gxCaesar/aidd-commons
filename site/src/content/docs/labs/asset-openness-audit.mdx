## Preparation and learning objectives

This laboratory serves `t10-asset-openness-reproducibility`. It teaches you to read inference code, training code, weights, architecture, data recipe, training data and evaluation code as separate claims. You will also trace each recorded claim to an evidence entry, distinguish access from licence scope, and identify records whose scope text limits a grant. Read [Asset openness and reuse](/learn/structure-and-pockets/asset-openness-and-reuse/) first. Familiarity with YAML is useful.

Mode is fresh independent computation over a frozen protocol and the committed catalogue. Use the project Python 3.11 environment and CPU. The commands need no network, download or accelerator. The `check` and `show` commands write nothing. The exporter overwrites only the committed compact summary after all checks pass.

```bash
.venv/bin/python labs/asset_openness_audit/run_lab.py check
.venv/bin/python labs/asset_openness_audit/inspect_asset_openness_audit.py show
.venv/bin/python labs/asset_openness_audit/inspect_asset_openness_audit.py check
.venv/bin/python labs/asset_openness_audit/export_summary.py
.venv/bin/python -m pytest labs/tests/asset_openness_audit -q
```

## Source records and checks

The input is the 228 committed YAML records in the resource catalogue snapshot recomputed on 2026-10-25. The protocol declares the examined 24 identifiers and their order. The loader refuses a missing identifier or invalid calendar date. The inspector prints each recorded dimension value with its evidence identifiers and review date. It also prints licence names and verbatim scopes, access evidence and caveats. A non-`unverified` claim must reference an evidence entry in its own record. A licence must carry a name, scope and resolving evidence reference.

The scope flag uses a case-insensitive whole-word match for `only`, `not`, `no separate terms` or `does not`. It is a text filter for teaching. It does not decide what a licence legally permits. A missing one of the 7 openness fields is a defect, not an invitation to fill it with `unverified`.

## Limits of the material

The audit checks what these catalogue records state and whether their references resolve internally. It does not reopen every linked external page, run a model or determine whether a resource can be used for a particular purpose. An `unverified` value is bounded by the source review and date recorded for that field. It is not evidence of absence. A `not_applicable` value states a different judgement about the resource type and retains its evidence entry. The frozen selection illustrates the distinctions and is not a representative sample of all resources.
