## Preparation and learning objectives

Read the [construct identity lesson](/learn/biologics-design/construct-identity-and-objectives/) first. This laboratory asks what each therapeutic entity's own record states about its molecular identity. You will reproduce field coverage, distinguish native protein information from a product-specific construct, and explain why a missing production host prevents a source record from defining that construct. You will also distinguish disagreement between stated values from differences in coverage. The [canonical English guide](/labs/biologic-construct-audit/) is this page.

## Mode and commands

The mode is fresh independent computation under a frozen protocol. Use the project Python 3.11 environment and CPU. No accelerator or additional dependency is needed. For a fresh network fetch, `download` requests the declared UniProt search, its individual entries and selected DailyMed labels. It records the exact URLs, response lengths, source versions and UTC retrieval time. It replaces the embedded source snapshot only after validation.

```bash
.venv/bin/python labs/biologic_construct_audit/run_lab.py download
.venv/bin/python labs/biologic_construct_audit/inspect_biologic_construct_audit.py show
.venv/bin/python labs/biologic_construct_audit/inspect_biologic_construct_audit.py check
.venv/bin/python labs/biologic_construct_audit/export_summary.py
.venv/bin/python -m pytest labs/tests/biologic_construct_audit -q
```

For an offline fresh independent computation, retain the committed source snapshot and start with the following commands. They read the same selected passages that produced the committed observations below.

```bash
.venv/bin/python labs/biologic_construct_audit/inspect_biologic_construct_audit.py show
```

`show` prints the source-level audit and normalized field values. `check` recomputes its invariants and exits non-zero on failure. Both write nothing. The exporter overwrites only the compact summary after the protocol and audit checks pass. It writes no summary when a check fails. A later live fetch can change the source passages, so the tables below describe the recorded snapshot.

## Records and four-field rules

The counted unit is one named therapeutic entity. A UniProt accession can mention several products, so its pharmaceutical annotation is read for each selected product separately. DailyMed contributes the declared description and mechanism passages. Native protein function, target cross-references and disease indications cannot fill a missing product-specific field.

| Field | Stated rule |
| --- | --- |
| Modality | Count the product's explicit biological class in its label. A reviewed UniProt protein entry that names the pharmaceutical product and protein establishes the broad protein modality. |
| Construct | Count product-specific components, assembly or sequence alteration in the selected passage. A product name or an unspecified glycosylation difference is insufficient. Retain whether the passage distinguishes the parts of a multi-chain entity. |
| Expression system | Count a named production host explicitly linked to the product. The native source organism does not establish an expression host. |
| Intended function | Count an explicit product action in the pharmaceutical annotation or mechanism section. An endogenous protein's function or a disease indication does not supply it. |

A field counts at entity level when an admitted source record states it. Source records remain separate. Definition status requires modality, product-specific construct and production host together in the same record. Function remains a separate fourth field. A modality alone is not a construct, and a construct without a production host does not satisfy the definition rule.

## Constructs and production hosts

The source-level audit preserves assembly and distinguished multi-chain parts separately from the construct flag. An unstated assembly or an undistinguished part describes the selected passage's coverage.

| Entity | Source | Assembly stated | Multi-chain parts distinguished |
| --- | --- | --- | --- |
| adalimumab | DailyMed | heavy and light chains | yes |
| agalsidase-beta | DailyMed | homodimer | yes |
| agalsidase-beta | UniProt | unstated | no |
| etanercept | DailyMed | dimer | yes |
| etanercept | UniProt | unstated | no |
| human-insulin-humulin | UniProt | unstated | no |
| insulin-lispro | UniProt | unstated | no |
| reteplase | UniProt | unstated | no |

Etanercept's UniProt passage names the receptor and Fc components without stating their assembly. Its DailyMed description supplies the dimeric assembly and CHO production host. The selected Humulin passage names a product without specifying its construct or host. The underlying medicine does not acquire those omissions from this record.

| Source-level gap | Entities | Source |
| --- | --- | --- |
| Construct stated without production host | etanercept, insulin-lispro, reteplase | UniProt |
| Production host stated without construct | agalsidase-beta | UniProt |

The known-bad tests present a modality-only record reported as defined and a construct reported as defined without a host. The audit refuses both. A record with neither a construct nor a host also cannot be reported as defined.

## Differences between sources

Only fields stated by both sources are compared for disagreement. Silence in one source remains a coverage difference. The committed comparison found no disagreement in the jointly stated fields and found the following coverage differences.

## Independent interpretation

Use `show` to explain why agalsidase-beta is defined in its DailyMed record but remains undefined in its UniProt record. Then explain why the Humulin passage cannot be reported as defining a construct. Decide whether the missing fields in either record establish anything about the medicine itself.

<details data-worked-answer>
<summary>Worked answer</summary>

DailyMed states agalsidase-beta's modality, homodimeric construct and CHO production host together. The selected UniProt passage states a host but supplies no product-specific construct under the frozen rule, so that source record remains undefined. Its missing intended-function statement is recorded separately. The Humulin passage supplies modality alone. Neither omission shows that the therapeutic entity lacks a construct, a production host or a biological function.

</details>

## Limits of the material

The audit reads what each entity's own selected record states. A field the record does not state is not a field the entity lacks. The product list is a bounded teaching cohort, and the selected passages do not measure coverage across all therapeutics or complete source records. Counts of stated fields do not rank the entities. A record that satisfies the definition rule does not thereby establish developability or therapeutic-candidate status. Reader learning has not been observed.
