## Preparation and learning objectives

This laboratory supports `t13-specificity-negative-selection`. It asks whether an affinity archive contains observations against alternative partners. After completing it, you should distinguish source rows from counted protein pairs, reproduce the partner distribution, and state why a single observed partner supplies no margin. Read the [independent-unit lesson](/learn/biologics-design/affinity-table-independent-unit/) first. The [specificity lesson](/learn/biologics-design/specificity-and-negative-selection/) explains the interpretation. The [canonical English guide](/labs/specificity-margin-audit/) is this page.

Mode is fresh independent computation under the frozen protocol. Use the project Python 3.11 environment and CPU. Once the snapshot is cached, these commands need no network or accelerator. The download step keeps a separate cache copy. The inspection commands leave the committed summary unchanged. The export command overwrites only that small summary after its checks pass.

```bash
.venv/bin/python labs/specificity_margin_audit/run_lab.py download
.venv/bin/python labs/specificity_margin_audit/inspect_specificity_margin_audit.py show
.venv/bin/python labs/specificity_margin_audit/inspect_specificity_margin_audit.py check
.venv/bin/python labs/specificity_margin_audit/export_summary.py
.venv/bin/python -m pytest labs/tests/specificity_margin_audit -q
```

## What the laboratory reads

The [LiteFold mirror](https://huggingface.co/datasets/LiteFold/SKEMPI2) holds the SKEMPI 2.0 archive in a ragged JSONL representation. This laboratory uses the existing [affinity reader](/labs/skempi-affinity/) to validate row order, positional alignment and parsed values. It then reads the `Protein 1` and `Protein 2` labels from the validated primary value. It strips surrounding whitespace but does not merge aliases or reconstruct overflow fragments. A row enters a pair count only if both labels and at least one parsed affinity are present. Pair order does not change its identity.

The local computation on 2026-10-23 read 7085 rows. It found 2544 rows with at least one parsed measurement. Among these, 2487 had both protein labels and contributed to 102 distinct unordered pairs and 171 distinct protein labels. The remaining 57 measured rows lacked a complete pair of labels in this reader's primary value. They remain in the archive count and cannot be assigned to a partner. The summary records these counts and the complete per-protein table. A missing parsed field in this mirror is not proof that the upstream CSV lacked a value.

## Partner distribution

The opposite label in each counted pair is a partner. Repeated measurements with the same pair increase the measurement count but leave the distinct-partner count unchanged. The observed distribution is below.

| Distinct partners | Proteins |
| ---: | ---: |
| 1 | 154 |
| 2 | 9 |
| 3 | 3 |
| 4 | 3 |
| 5 | 1 |
| 6 | 1 |

The median distinct-partner count is 1. The inclusive-quartile interquartile range runs from 1 to 1. Exactly 154 proteins have one measured partner. Only 9 counted pairs have more than one observed partner on both sides. This is a coverage criterion. It does not establish that any pair has a usable quantitative margin.

## Limits of the material

This census does not estimate a selectivity margin, say that a protein is selective, or treat a protein with one observed partner as measured against alternatives. It makes no prediction for unmeasured proteins and no ranking by row or partner count. Labels are not entity-resolved, so a differently written alias could change a count. The 57 measured rows without both labels cannot repair that limitation. No reader learning outcome has been observed.
