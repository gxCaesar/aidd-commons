## 运行之前

**模式：对已提交文件做可运行的检查。** 该命令读取与它同目录、已冻结的资源登记表切片，
其中是 31 个做出结构类或亲和力类主张的登记系统。它不发起网络请求、不下载任何结构、
不导入第三方包、也不做任何预测。它不评估任何系统的准确度。它回答的是一个比准确度更靠前的
问题：这个系统的输出，究竟是关于什么的一项主张？

```bash
python labs/cofolding_claims/inspect_claims.py show
```

一个预测出的单体、一个预测出的复合物、一个共折叠出的蛋白—配体位姿、一个对接产生的位姿，
以及一次实验测得的结合数据，都可能以"带着一个分数的坐标文件"的形式到你手上。文件格式区分不了
它们，词汇也区分不了。登记表可以，因为每条记录都写明了它执行的任务，以及它的证据到哪里为止。

家族成员资格只由声明的任务决定，别无其他。`export_claim_records.py` 选入所有任务与五个类定义
有交集的记录，因此任何系统都无法被手工塞进这个家族、也无法被悄悄排除在外；而且除非明确要求，
导出脚本不会覆盖既有切片，并会逐条点名将会发生变化的记录。

## 1. 模态标签叫不出主张的名字

第一个区块把家族中每个登记系统按其任务所许可的主张归类。请同时看旁边的模态一列。
标签 `biomolecular-complex` 出现在三个不同的主张类别之下，`small-molecule` 也是三个。

这是读者被从一种主张挪到另一种主张而毫无察觉的第一处。两个系统可以都被标为面向复合物，
而其中一个预测结构、另一个估计亲和力；一句"它在复合物上有效"对两者都成立，含义却完全不同。

## 2. 一个系统可以同时做两种主张

31 个系统里恰好有一个同时声明了共折叠复合物与亲和力估计：`model-boltz-2`。
这不是记录的缺陷，而是一个真实模型的真实属性，也正是两种主张最容易被合并的地方。

位姿与效力是同一次运行的两个独立输出。其中一个好，并不使另一个也好。它们可以在同一批化合物上
彼此不一致；一个刚看过一张有说服力的结构图的读者，并没有因此获得关于该化合物是否有活性的任何
信息。

## 3. 这里面没有一条是实验测量

第三个区块打印这个家族中出现的记录类型。它们是模型、软件、模型资产、基准和一篇论文。
没有一条是测量记录。

实验结合证据完全住在别处，住在一条描述测定及其条件的记录里。这个家族中的任何条目，
都不能被用来说明一个化合物在实验中究竟做了什么，无论它的结构输出看上去多好。

## 4. 核对登记表能支撑什么、不能支撑什么

```bash
python labs/cofolding_claims/inspect_claims.py check
```

共十项检查。它们确认切片与检查器按同样的五个类别归类，确认每条被抽取的记录都是凭声明的任务
而不是凭名字进入家族的，确认每个系统都带有复核日期，确认没有任何共折叠系统同时为其训练数据
与准确度主张背后的代码提供证据，确认恰有一个系统同时主张位姿与亲和力，确认没有测量记录藏在
家族里，并确认至少有一个模态标签横跨了不止一个主张类别。

这个家族在训练数据这一维上并不一致，检查项因此把它说出来而不是替它假定。三个系统里有一个
公开了预处理后的训练数据与训练代码，另外两个没有；三个都没有公开评测代码。三个系统共同成立
的是，产生报告数字的那份代码不在那里可供阅读。

有一项值得读两遍。**这个家族里没有任何共折叠系统为其准确度主张背后的评测代码提供了证据。**
推理代码与权重往往可得，产生那些报告数字的代码则不可得。家族里更宽的两个系统确实公开了各自的
评测脚本，即 DiffDock 的发布版本与 RosettaFold 的全原子发布版本，检查项把这两个例外写出来而不是
把它们藏起来。这是一句关于"已经公开了什么"的陈述，不是关于"那些数字对不对"的陈述；它意味着，
共折叠系统的准确度主张目前只能被采信，而不能从源头重新核对。

## 独立练习

一位同事发来一个预测的蛋白—配体复合物，并写道："这个模型在它的论文里达到了配体 RMSD 中位数
0.8 埃，所以这个位姿足够可靠，我们可以把这个化合物排进合成优先级。"

请说出这句话把哪几项彼此不同的主张串在了一起，并逐项说明这份登记表能否支撑它。

<details data-worked-answer>
<summary>参考答案 —— 三项主张，以及登记表够得着哪一项</summary>

**主张一，那个报告出来的准确度。** 一个基准集上的中位数是那个集合的属性，不是你这个靶点的属性。
即便照单全收，它也没有讲最难的那些例子，而中位数恰恰盖住了尾部——位姿错到足以改变决定的那一侧。
登记表能定位到这个系统和它的任务，并且显示共折叠系统以及这个家族31 个系统中的 24 个
都没有评测代码的证据，所以这个数字无法从已公开的产物重新核对。它可以被引用，但在这里无法被核实。

**主张二，这个位姿是对的。** 基准集上的中位数不会迁移到一个新的复合物上，而登记表关于你这个
靶点什么也没有。这正是模态标签最容易误导的地方：这个系统被标为面向复合物，你这个案例是复合物，
于是句子就从前者滑到了后者，中间没有任何论证。

**主张三，这个化合物值得合成。** 这是一项关于效力与可成药性的主张，而这个家族中没有任何一条是
测量记录。一个正确的位姿完全可以配上一个无活性的化合物。登记表能告诉你的，至多是这个系统是否
同时声明了亲和力任务——那是第二个预测，仍然不是一次测量。

一份完整的回答会注意到：这三项主张需要三种不同的证据，而那句话只为三项一起提供了一个数字。
有用的回复不是"你的模型不对"，而是"这三件事你想确立哪一件，以及什么才能确立它"。

</details>

## 它不做什么

这条路径不运行共折叠模型、不评估任何模型、也不对任何系统排名。它无法告诉你一个预测是否准确。
它读的是本仓库维护的登记表中的声明与证据状态，因此它的权威性恰好等于那些记录的权威性，
而每条记录自己的注意事项与复核日期都会随之一起传递。openness 为 `unverified` 意味着
"在记录的日期上复核了声明的检索面，未在其中找到该产物"，而不是"该产物不存在"。
