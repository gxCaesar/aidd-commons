## 准备与学习目标

本实验对应 `t10-asset-openness-reproducibility`。你将分别阅读推理代码、训练代码、权重、架构、数据配方、训练数据和评测代码的主张，并追溯各主张的证据条目。你还将区分访问级别与许可证范围，找出范围文字中限制授权的记录。请先阅读[资产开放性与复用](/zh-cn/learn/structure-and-pockets/asset-openness-and-reuse/)。了解 YAML 会有所帮助。

模式是依照冻结协议，对已提交目录进行全新独立计算。使用项目的 Python 3.11 环境和 CPU。命令无需网络、下载或加速器。`check` 与 `show` 不写入文件。导出程序仅在全部检查通过后覆盖已提交的精简汇总。

```bash
.venv/bin/python labs/asset_openness_audit/run_lab.py check
.venv/bin/python labs/asset_openness_audit/inspect_asset_openness_audit.py show

```

## 来源记录与检查

输入是于 2026-10-25 重新计算的资源目录快照中已提交的 232 条 YAML 记录。协议按顺序声明所检查的 24 个标识符。加载器拒绝不存在的标识符或无效的日历日期。检查器逐项输出开放性字段的记录值、证据标识符和复核日期，也输出许可证名称及原文范围、访问证据和注意事项。任何非 `unverified` 的主张都必须引用本记录中的证据条目。每份许可证都必须有名称、范围和可解析的证据引用。

范围标记对 `only`、`not`、`no separate terms` 或 `does not` 作忽略大小写的完整词匹配。这是教学用的文本筛选，不判断许可证在法律上准许什么。缺少 7 个开放性字段中的任何一个是缺陷，不能自行补作 `unverified`。

## 材料局限

本实验核查目录记录的陈述和内部证据引用是否可解析。它不会重新打开每个外部链接、运行模型，或判定某项资源是否可用于特定目的。`unverified` 只反映相应字段已记录的来源审阅及日期，不证明资产不存在。`not_applicable` 是关于资源类型的另一种判断，并保留它的证据条目。冻结选集用于说明区别，并非全部资源的代表性样本。
