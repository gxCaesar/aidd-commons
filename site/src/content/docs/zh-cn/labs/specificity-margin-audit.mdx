## 准备与学习目标

本实验对应 `t13-specificity-negative-selection`，检验亲和力档案是否包含针对其他伙伴的观测。完成后，你应能区分来源行与计入统计的蛋白配对，复现伙伴分布，并说明为什么只有一个已观测伙伴不能提供边际。请先阅读[独立单元课程](/learn/biologics-design/affinity-table-independent-unit/)。[特异性课程](/learn/biologics-design/specificity-and-negative-selection/)解释结果的含义。[英文原版指南](/labs/specificity-margin-audit/)是规范版本。

模式为按冻结协议进行全新独立计算。使用项目的 Python 3.11 环境和 CPU。快照缓存后，以下命令不需要网络或加速器。下载步骤使用单独的缓存副本。检查命令不改动已提交的汇总。导出命令只在检查通过后覆盖小型汇总。

```bash
.venv/bin/python labs/specificity_margin_audit/run_lab.py download
.venv/bin/python labs/specificity_margin_audit/inspect_specificity_margin_audit.py show
.venv/bin/python labs/specificity_margin_audit/inspect_specificity_margin_audit.py check
.venv/bin/python labs/specificity_margin_audit/export_summary.py
.venv/bin/python -m pytest labs/tests/specificity_margin_audit -q
```

## 实验读取的材料

[LiteFold 镜像](https://huggingface.co/datasets/LiteFold/SKEMPI2)以宽度不齐的 JSONL 表示 SKEMPI 2.0 档案。本实验复用已有的[亲和力读取器](/labs/skempi-affinity/)，验证行顺序、按位置对齐及解析后的数值，然后从已验证的主值读取 `Protein 1` 和 `Protein 2` 标签。它只去除标签首尾空白，不合并别名，也不从溢出片段重建字段。只有两个标签齐全且至少有一个解析后的亲和力值时，该行才计入配对。配对的先后顺序不改变其身份。

2026-10-23 的本地计算读取了 7085 行，其中 2544 行至少有一个解析后的测量值。在这些行中，2487 行包含两个蛋白标签，构成 102 个不同的无序配对和 171 个不同的蛋白标签。其余 57 个有测量值的行在读取器的主值中缺少完整的配对标签，因此保留在档案行数中，却不能分配伙伴。汇总记录了这些计数和完整的逐蛋白表。镜像中解析字段缺失不能证明上游 CSV 缺少该值。

## 伙伴分布

每个计入统计的配对中，对面的标签就是伙伴。同一配对的重复测量增加测量行数，但不增加不同伙伴数。观测分布如下。

| 不同伙伴数 | 蛋白数 |
| ---: | ---: |
| 1 | 154 |
| 2 | 9 |
| 3 | 3 |
| 4 | 3 |
| 5 | 1 |
| 6 | 1 |

不同伙伴数的中位数为 1。按含端点四分位数定义，四分位区间从 1 到 1。恰有 154 个蛋白只有一个已测量伙伴。仅有 9 个计入统计的配对，其两侧蛋白都各有超过一个已观测伙伴。这是覆盖度条件，不能证明任何配对具有可用的定量边际。

## 材料的限制

这项清点不估计特异性边际，不断言某个蛋白具有特异性，也不把只有一个已观测伙伴的蛋白视作已经对其他伙伴测量。它不预测未测量蛋白，也不按行数或伙伴数排名。标签未经实体归一化，不同写法的别名可能改变计数。缺少两个标签的 57 个有测量值的行不能消除这一限制。尚未观测到读者学习成效。
