## 运行之前

**模式:在一个实时、带版本号的数据库快照上做独立计算。** 本实验中没有任何地方
拟合过模型。它的范围按设计是窄的:只覆盖内在清除率,是其分类主题所列几项
PK 暴露度量中的一项。剩余度量(吸收、分布、口服生物利用度)的另外两个候选
数据来源已于 2026-09-12 查证并被否决:一个常用聚合站点列出的四个数据集中
有三个都溯源到普通的封闭获取期刊论文,查不到可独立核实的开放授权;第二个
真正 CC BY 4.0 的数据库,把实际测量数值限定给通过身份验证的用户。见
`docs/ROADMAP_V0.2.md`,2026-09-12。

```bash
python labs/az_clearance_system/run_lab.py download   # 抓取并缓存实时快照
python labs/az_clearance_system/inspect_az_clearance_system.py show
python labs/az_clearance_system/inspect_az_clearance_system.py check
```

需要 Python 3.11 或更新版本、NumPy、SciPy 与 RDKit。只有一次性下载需要联网,
来源是公开的 ChEMBL REST API;一旦 `.cache/az_clearance_system/` 下的缓存
存在,就不再需要联网。

## 为什么是这份文献,为什么是三个具名检测

这里的数据来自一份真实、可引用的 ChEMBL 数据集存档,
[文献 `CHEMBL3301361`](https://www.ebi.ac.uk/chembl/explore/document/CHEMBL3301361),
"Experimental in vitro DMPK and physicochemical data on a set of publicly
disclosed compounds"(阿斯利康,Mark Wenlock 与 Nicholas Tomkinson,2016年),
不是某篇付费论文的替代品。它报告了三个具名检测下的内在清除率:人肝微粒体、
人肝细胞、大鼠肝细胞。`protocol.json` 只按检测 ID 准入这三个,因为它们正是
这份文献自己区分开的体系,并读取每个检测自己的描述文字来核实其物种与基质。

## 一条适配真实差异的准入规则

这个终点的真实数据,并不像姊妹 IC50 实验那样用 `standard_relation="="`
表示精确值。这里,空的 `standard_relation` 字段才是精确值,而 `"<"` 或 `">"`
标记的是超出该检测自身可定量范围的读数,例如检测描述中所写的
"&lt;3 to &gt;150 microL/min/mg"。一条记录只有在其关系字段为空、
`standard_flag=1`、`potential_duplicate=0`、不带数据有效性备注、其分子是
自身的母体、结构在 RDKit 下有效,并且两个独立报告的数值字段彼此一致时,
才会被准入。于 2026-09-12 计算:

| 检测 | 物种 | 基质 | 输入行数 | 被准入的母体分子 |
| --- | --- | --- | ---: | ---: |
| `CHEMBL3301370` | 人 | 微粒体 | 1,102 | 743 |
| `CHEMBL3301371` | 大鼠 | 肝细胞 | 837 | 592 |
| `CHEMBL3301372` | 人 | 肝细胞 | 408 | 288 |

在这三个检测的任何一个里,都没有母体分子带有一条以上的活性记录,所以本次
运行没有发生中位数聚合;`show` 仍会报告重复母体计数,这样未来若重新抓取
真的发现了重复,也不会被漏报。

微粒体检测报告的清除率是按每克微粒体蛋白计(`mL.min-1.g-1`);两个肝细胞
检测报告的是按每百万个全细胞计(`uL.min-1.(10^6cells)-1`)。这是两种不同的
物理基准,不是同一物理量的两种单位,本协议也没有对它们做任何换算。
Spearman rho 和 Pearson r 不受这个差异影响:两者对任意一侧的固定单调重
标度都不变,而换单位正是这样一种重标度。但两个体系数字之间的原始比值不是
这样——`show` 为涉及微粒体的两对比较打印的 `log10 ratio`,是对报告数值的
一次真实、确定性的计算,但它不像两个肝细胞检测之间的比值那样是清除率的
字面倍数关系,因为两个肝细胞检测共用同一单位。对这两对涉及微粒体的比较,
应把它读作一个同方向的大小信号,而不是物理量级。

## 三次比较,两个变量

`show` 报告了全部三个两两重叠,尽可能各自固定一个变量:

| 比较 | 变化的是什么 | 重叠数 | 完整集合 Spearman rho | 干净子集 Spearman rho |
| --- | --- | ---: | ---: | ---: |
| 人肝细胞 vs 大鼠肝细胞 | 物种,基质固定 | 106 | 0.4732 | 0.4732 |
| 人肝微粒体 vs 人肝细胞 | 基质,物种固定 | 96 | 0.4864 | 0.4864 |
| 人肝微粒体 vs 大鼠肝细胞 | 两者都变 | 359 | 0.3868 | 0.3868 |

完整集合与干净单一配对子集在这里完全一致,是因为本快照里没有任何母体分子
在任何一个检测下带有重复的被准入活性;不论如何,`check` 都会断言干净子集
始终是完整重叠的子集。三个相关性都是真实且为正的,但都远低于 1:仅仅换
物种,或仅仅换基质,在秩次意义上就已经丢失了一半以上的预测力。

## 相关系数掩盖了什么

`show` 报告的具名分歧例子,取自最干净的单变量比较(物种变化,基质固定在
肝细胞):

| 化合物 | 人肝细胞清除率 | 大鼠肝细胞清除率 | log10 比值 |
| --- | ---: | ---: | ---: |
| `CHEMBL361546` | 135 | 14.8 | +0.96 |
| `CHEMBL1229592` | 3.31 | 79.4 | −1.38 |

这两个真实化合物在两个物种下都进入了被准入集合;一个在人肝细胞中的清除
速度大约是大鼠的九倍,另一个在大鼠中的清除速度大约是人的 24 倍。对这一对
检测而言,并不存在唯一的跨物种清除率比值;一个主张需要说明是哪个化合物,
并引用实际测得的那一对数值。

## 这没有展示什么

本协议只读取来自一份文献的体外内在清除率记录。它对吸收、分布容积或口服
生物利用度——其分类主题所列的其他 PK 暴露度量——未作任何陈述,也不作任何
因果或人体剂量主张:两个检测体系间的体外清除率分歧,不是一个前瞻性的
相互作用或给药陈述。完整的、机器可读的清单见 `protocol.json` 的
`excluded_by_design`。

## 独立练习

一张汇总表写道:"化合物 Z:CL = 22",没有更多细节。

1. 仅使用 `show` 报告的内容,说出这个数字缺失的两个(不是一个)轴,并从
   上面的表格中给出一个真实化合物,说明若其中任一个轴改变,它的数值会
   看起来完全不同。
2. "人肝细胞 vs 大鼠肝细胞"和"人肝微粒体 vs 人肝细胞"这两次比较都落在
   Spearman rho ≈ 0.48 附近。这种相近是否意味着物种和基质是通过同一种
   机制影响清除率的?除了本协议之外,你还需要什么才能把这两种机制区分开?

<details data-worked-answer>
<summary>参考答案</summary>

缺失的两个轴是物种(人 vs 大鼠)和基质(微粒体 vs 全细胞肝细胞);本协议
恰恰因为这两者都能独立改变这个数字,才准入了三个具名检测。`CHEMBL361546`
在人和大鼠肝细胞之间相差接近十倍,两侧单位相同,所以这在固定另一个轴的
前提下是一个真实的倍数关系。"微粒体 vs 肝细胞"这一对给不出同样干净的
例子:它的两个检测报告清除率的物理基准不同(每克微粒体蛋白 vs 每百万个
全细胞),所以像 `CHEMBL2181927` 或 `CHEMBL1916271` 这样的原始比值,只是
说明两个体系朝同一方向出现了真实的分歧,而不像肝细胞那一对的数字那样是
字面上的倍数关系。两对比较相近的相关系数,并不是共享机制的证据:物种间的
代谢差异,与亚细胞组分相对全细胞组成的差异,是两种截然不同的生物学原因,
却可能碰巧产生数值相近的秩相关。要把它们区分开,需要对每个轴分别做机制
研究,而本协议只读取这三个检测报告的清除率数值,并不提供这个。
