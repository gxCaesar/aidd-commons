## 运行之前

**模式：对已提交声明做可运行的检查。** **不运行任何对接程序**、不准备任何结构，
报出来的数字是示意值而不是结果。

```bash
python labs/docking_protocol/inspect_protocol.py show
```

一个对接分数以"带单位的数字"的形式到达，这就邀请你把它与任何带同样单位的数字相比。
**而它是七个已声明选择的输出。**

## 1. 五个组件挪动数字，两个挪动它的含义

**搜索、位姿生成、打分、重打分、约束**各自都会改变那个数字。
搜索量不同就会找到不同的位姿，因此"找到的最好分数"既是配体的属性、也是搜索的属性。
一个约束会把某些位姿从考虑中移除，于是它改变了哪一个位姿最好。

**诱饵与验证**完全不改变任何分数。它们决定的是"是否存在一个富集数字"，
以及"这些分数是否曾被核对过表现得像分数"。**这恰恰是这两个最容易被略去的原因：
一个不带它们的协议照样能产出满满一列数字。**

## 2. 最干净的一对"不可比较"

`p-baseline` 与 `p-rescored` **恰好只差一个组件**。
同样的搜索、同样的位姿生成、同样的打分函数、同样的约束、同样的诱饵、同样的验证。
同一个配体、同一个结构。

其中一个对最优位姿施加了第二个打分函数。

| 协议 | 报出的分数 |
| --- | --- |
| `p-baseline` | **-8.2** |
| `p-rescored` | **-10.7** |

两者都是 kcal/mol。**配体没有任何变化，那 2.5 的差距完全来自协议。**
第二个数字来自另一个函数，所以两者不在同一个标度上。

## 3. 这一组里没有任何一对可以比较

命令会算出每一对，并点名是哪些组件把它挡住的：

- `p-baseline` 对 `p-rescored`：被重打分挡住
- `p-baseline` 对 `p-constrained`：被搜索与约束挡住
- `p-rescored` 对 `p-constrained`：被搜索、重打分与约束挡住

**共享单位不等于共享标度。** 三个协议、三个数字、同一个参照配体，
而它们之间**没有一个合法的比较**。

## 4. 一个没有验证的协议报不了什么

```bash
python labs/docking_protocol/inspect_protocol.py check
```

`p-constrained` 既没声明验证也没声明诱饵。实验把它因此**报不了的东西**记下来：
**任何"它的分数表现得像分数"的主张**（因为什么都没被验证），
以及**任何富集数字**（因为没有诱饵集可供富集）。

共十一项检查。**一个没有被完整声明的协议会在任何比较被尝试之前就中止运行**，
因为对着一个未声明的协议做比较，不是比较。

## 独立练习

一张幻灯片比较两个系列："系列 A 对接分数 -9.4，系列 B 是 -7.1。我们推进 A。"
方法部分写明：这两个系列是**在不同时间、由不同的人、用同一个程序**对接的。

请说出在这个比较有意义之前你需要确立什么，以及如果那些信息已经不存在了你会怎么做。

<details data-worked-answer>
<summary>参考答案 —— 五个问题，以及退路</summary>

**同一个程序不等于同一份协议。** 五个会挪动数字的组件，在同一个程序的两次运行之间都可能不同：
穷尽度、盒子的定义与留白、构象与质子化状态是怎么生成的、选了哪个打分函数、
有没有做重打分、有没有施加约束。**其中任何一个，都足以让 -9.4 与 -7.1 处在不同标度上。**

**这里有两个特别可能不同。** "不同时间、不同的人"通常意味着**盒子定义不同**，
因为盒子是围着当时手头有的参照物手工画的。而**穷尽度**是运行看起来没收敛时人们会调高的设置，
**于是被更用力做过的那个系列，倾向于带着更大的数字。**

**验证是那个谁都拿不出来的东西。** 即便两份协议一致，一个分数有意义也只有在协议被核对过时——
通常是把参照配体重新对接并报出 RMSD。如果两次运行都没有这个，
那么比较的是两个未经验证的量，**而且即使协议一致也救不回来。**

**如果信息已经没了怎么办。** 不要凭记忆重建，也不要"加个注意事项"就去比这两个数字——
**因为注意事项不会跟着数字走到下一张幻灯片上。**
**在一份声明好的协议下，把两个系列重新对接一遍。**
相对于这个决定它很便宜，它产出的数字**按构造就是可比的**，
而且这是唯一一条能以一句站得住的话收尾的路径。

如果重新对接不可行，诚实的报告是：**这两个数字无法比较，
推进决定所依据的是那些不是对接分数的证据。**

</details>

## 它不做什么

它不运行对接程序、不准备结构，也不确立任何分数是正确的。
它读的是声明，并报告这些声明允许哪些比较。

**一个报出来的对接分数，是某一次特定搜索在某个特定打分函数与特定约束下找到的最好的数字。**
它不是结合自由能、不是活性预测，**也不能与另一份协议产出的数字相比较。**
