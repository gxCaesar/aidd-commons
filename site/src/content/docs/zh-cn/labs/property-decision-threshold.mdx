## 运行之前

**模式：对已提交文件做可运行的检查。** 两条命令读取已完成的 FreeSolv 基线与一条冻结的决策规则。
不拟合任何东西、不运行任何模型，也没有任何化合物被推荐去做什么。

```bash
python labs/property_decision/inspect_decision.py evidence
```

点预测**总能**给出一个决定，因为一个数字总是落在阈值的某一侧。**区间不会。**
下面的一切都源自认真对待这一点。

## 1. 四个组合里只有一个达到了它被构造出来要达到的覆盖率

这些区间是分裂共形（split-conformal）区间，在验证划分上校准，目标名义覆盖率为 0.9。
第一条命令把每个划分与模型，连同它在测试上**实际**达到的覆盖率一起打印出来。

只有 **scaffold morgan_random_forest** 达到了，为 0.90625。另外三个都不足，其中一个差得很远：
**random morgan_ridge 的覆盖率是 0.734375**，相对它被构造出来要达到的目标短缺 0.1656。

现在看旁边那一列带宽。random morgan_ridge 拥有四者中**最窄**的带，3.1653 kcal/mol。
而真正达到覆盖率的那个组合拥有**最宽**的带，6.0130。

**一个更紧的区间并不是更好的区间，除非它仍然覆盖得住。** 这里最窄的那条带是最不可信的一条，
而它的宽度本身不会说出这件事。

## 2. 弃权带

```bash
python labs/property_decision/inspect_decision.py decide
```

冻结规则在整个区间都低于阈值时推进，在整个区间都高于阈值时否决，
并在**区间跨过阈值时弃权**。因此弃权带宽度是两个半径，以阈值为中心，命令会打印它的边界。

只施加在点估计上时，全部 29 个网格点都会得到一个决定。在区间规则下则不会。
两者之差恰好就是那条带，而且它不是一个小修正：最宽的情形下 29 个里有 13 个无法决定。

## 3. 更可信的区间决定得更少

这才是本题真正要讲的取舍，而且已提交的数字让它呈现单调。按带宽排序：

| 划分与模型 | 弃权数 | 覆盖率 |
| --- | --- | --- |
| random morgan_ridge | 29 里 7 个 | 短缺 0.1656 |
| random morgan_random_forest | 29 里 11 个 | 短缺 0.0250 |
| scaffold morgan_ridge | 29 里 11 个 | 短缺 0.0250 |
| scaffold morgan_random_forest | 29 里 13 个 | 达到名义值 |

**达到名义覆盖率的那个组合弃权最多。** 随着带变宽，覆盖率短缺无一例外地下降，
并有一项检查把这个次序锁住。

决定得更多不等于对得更多。一个什么都能决定的模型并没有解决问题，
它只是拒绝表示自己的不确定性；而看上去更容易的那个划分，是在赊账买信心。

## 4. 两条准则不一致，而且在两个划分上朝同一个方向

规则在读到数字**之前**就声明了两条选择准则：点准则取最低平均绝对误差，
区间准则取从上方最接近名义值的覆盖率。

在两个划分上，点准则都选中 `morgan_ridge`，区间准则都选中 `morgan_random_forest`。
**误差最低的模型，并不是区间能支撑一个阈值决策的那个模型。**
由于这个不一致在两个划分上指向同一方向，它不是划分带来的偶然，并且有一项检查也要求这一点。

事先声明两条准则，正是让这件事可被报告的原因。事后再选，两条中的任何一条
都能为一个早已被偏好的模型辩护。

## 5. 它算不出什么

**有多少真实化合物落在这条带里。** 已完成的实验提交的是聚合指标与划分成员表，
不是逐化合物的测试预测，因此这条带可以在预测轴上被测量，却无法被填充。

上面那些网格计数是在一个声明范围上的算术。它们**不是分子的样本**，不可以被当作通过率来读。
命令会把这条限制打印出来，而不是留给读者去察觉——
这与[反证档案](/zh-cn/labs/counterevidence-dossier/)在本仓库别处清点的
"承认自身记录缺口"属于同一类。

```bash
python labs/property_decision/inspect_decision.py check
```

共二十项检查。规则完整性是前置条件：当规则不完整时，它**根本不会被施加到证据上**。

## 独立练习

一位同事提议："我们模型的 MAE 是 1.13 kcal/mol，所以把预测低于 −5 的全部推进，其余否决。
如果第一批结果不理想，那些临界的以后再回头看。"

请说出这三个分句各自错在哪里，并给出在同意这个计划的任何版本之前，你会先要的那**一个**数字。

<details data-worked-answer>
<summary>参考答案 —— 三个分句，以及该要的那个数字</summary>

**"MAE 是 1.13，所以把低于 −5 的推进。"** MAE 并不许可这个阈值。
平均绝对误差是测试集上的一个平均量，它没有说任何单个预测可能离真值多远，
而阈值决策是一次一个化合物做出的。真正管这件事的量是已校准半径，
在同一划分同一模型上是 2.7394 —— **是 MAE 的两倍多。**
把 MAE 当区间用，会把不确定性低估约一倍，而且是朝着让计划显得更安全的方向。

**"其余否决。"** 这个分句藏起了那条带。所有没被推进的都变成否决，
于是证据无法分辨的那些化合物照样被分辨了——悄悄地，由点估计恰好落在哪一侧来决定。
而那些恰恰是最靠近阈值的化合物，也就是决策最要紧、证据最薄的那些。

**"那些临界的以后再回头看。"** 这把弃权当成了一个应急方案，而不是一个结果。
临界化合物已经被第二个分句否决掉了，因此根本不存在一个被记录下来的集合可供回头看。
弃权只有在决策发生的那一刻就是一个已声明的结果时才起作用——
这正是冻结规则有三个分支而不是两个的原因。

**该要的那个数字：已校准的区间半径，连同它在测试上实际达到的覆盖率、
以及它被构造出来要达到的名义覆盖率。** 单独一个数字不够——
一个不附覆盖率的半径是关于宽度的主张，不是关于可靠性的主张；
而本实验自己的证据恰恰显示，最窄的半径属于覆盖最差的模型。
有了半径你能算出那条带；有了覆盖率你才知道那条带是否有意义。

一份完整的回答还会注意到：从这份证据出发，没有任何阈值站得住。
实验里的规则自己写明了这一点：那个值是为教学声明的，
仓库里没有任何东西确立 −5 把有用的化合物与无用的化合物分开。

</details>

## 它不做什么

这条路径不拟合模型、不评估任何模型，也不确立那个阈值是正确的。
它把一条冻结规则施加到已提交的聚合量上，并报告规则无法分辨的部分。
一个"推进"结果的含义是：在一个回顾性基准上，一个已校准区间越过了一个声明的阈值，仅此而已。

证据来自 [FreeSolv 诚实基线](/zh-cn/labs/freesolv-honest-baselines/)实验。
