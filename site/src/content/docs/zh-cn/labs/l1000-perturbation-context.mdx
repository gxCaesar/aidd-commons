## 运行之前

**模式：在一个真实、带版本号的 GEO 序列上做独立计算。** 本实验中没有任何地方
拟合过模型。它为两个固定细胞系里每个被准入的化合物各读取恰好一条真实分子谱，
所以它对"在相关的生物学单位上编码分子谱、细胞状态、扰动、时间和实验语境"
这个问题的自己的回答是：这个单位就是——一个化合物在一个细胞系、一个给药量、
一个时间点下的中位数差异表达谱。

```bash
python labs/l1000_perturbation_context/run_lab.py download   # 抓取并缓存约 640 MiB
python labs/l1000_perturbation_context/inspect_l1000_perturbation_context.py show
python labs/l1000_perturbation_context/inspect_l1000_perturbation_context.py check
```

需要 Python 3.11 或更新版本、NumPy、SciPy、RDKit 与 h5py。只有一次性下载需要
联网，来源是公开的 GEO FTP 镜像；一旦 `.cache/l1000_perturbation_context/`
下的缓存存在，就不再需要联网。

## 为什么是这份文件，而不是更小或更大的文件

数据来自 [GEO 序列 GSE70138](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE70138)，
"L1000 Connectivity Map perturbational profiles ... LINCS PHASE II"。同一个
序列还发布过一份 2015 年日期的 Level 2 版本，用的是简化的列标签，例如
`A375-trt_cp-5`；直接抓取核实后，它的列标签**没有一个**出现在当前的元数据
文件里，因此它无法与真实的化合物身份、给药量或时间关联起来,没有被使用。
这个序列完整的 12,328 基因 Level 4(Z-score)与 Level 5(聚合信号)版本分别
是 14GB 与 5.4GB,远超本项目 CPU-first 的规模约定。本协议改为读取 978 个
landmark 基因的 Level 2 文件(直接测量,从不是推断值),并自己计算相对于
载体对照的差异化信号——用小得多的体量得到真实数据。

## 一个化合物、一个细胞系的准入规则

一个实体是一个真实化合物(`pert_id`,结构来自 GSE70138 自己的扰动剂目录,
经 RDKit 验证有效),处于两个固定细胞系(MCF7 或 PC3)之一,固定给药量
(10µM)和时间点(24h)。它的值是:每个重复孔自身的原始 Level 2 谱,减去
该重复孔所在那一块板上全部载体对照孔谱的中位数,再对重复孔取中位数;
若某个重复孔所在板没有载体对照,则被排除,不会与其他板的对照配对。
于 2026-09-12 计算:

| 细胞系 | 输入的化合物处理行数 | 被准入的化合物 |
| --- | ---: | ---: |
| MCF7 | 37,495 | 1,725 |
| PC3 | 34,112 | 1,724 |

两个细胞系都准入的化合物有 1,721 个。

## 为什么基线校正在这里不是可选项

`show` 会同时报告两种算法的结果。完全不做校正、直接用原始 Level 2 数值
计算一次:真实的、按化合物匹配的配对,Spearman rho 中位数为 0.79,但一个
确定性的**不匹配**化合物背景(每个化合物配上另一个固定的、不同化合物的谱)
中位数也有 0.70——两个细胞系的原始表达谱共享了太多背景结构,以至于不相关
的化合物也能强相关。对绝对表达值做朴素比较,几乎分不清真实信号和共享噪声。

做完本协议要求的按板匹配载体对照差异化之后:

| | 匹配(真实化合物配对) | 零假设(确定性错配) |
| --- | ---: | ---: |
| Spearman rho 中位数 | 0.175 | 0.034 |
| Spearman rho 均值 | 0.183 | 0.044 |
| 正值占比 | 79.5% | 60.3% |

对这两个分布做双侧 Mann-Whitney U 检验,给出 p = 7.9 × 10⁻⁸²:匹配分布与
零假设分布真实地、稳健地不同,不只是两个带噪声的点估计恰好不一样。

## 相关系数掩盖了什么

`show` 报告的具名例子:

| 化合物 | 跨细胞系 Spearman rho |
| --- | ---: |
| 雷公藤甲素(Triptolide) | +0.793 |
| 乌拉地尔(Urapidil) | +0.757 |
| 米托蒽醌(Mitoxantrone) | +0.721 |
| GDC-0879 | −0.528 |
| EX-527 | −0.516 |
| 安西奈德(Amcinonide) | −0.591 |

1,721 个经过基线校正的真实化合物里,约有五分之一呈现**负**的跨细胞系
相关性:对这些化合物而言,MCF7 与 PC3 之间不只是效应强弱不同,转录响应
的方向本身在两个细胞系之间发生了反转。

## 这没有展示什么

本协议只读取两个真实细胞系、一个真实给药量、一个真实时间点,而同一个
GEO 序列还包含另外数千种细胞系、给药量、时间点和扰动类型(shRNA 敲低、
基因过表达);也只使用 978 个直接测量的 landmark 基因,从不使用这个序列
同样报告的 11,350 个计算推断出的基因。它不主张跨细胞系信号相关性能预测
任何具名化合物的临床或体内结局。完整的、机器可读的清单见 `protocol.json`
的 `excluded_by_design`。

## 独立练习

一张图注写道:"化合物 Q 的转录信号高度可复现(rho = 0.79)。"

1. 仅使用本实验计算出的内容,说出这句话缺失了什么,才能让你判断这个 0.79
   反映的是化合物本身,还是本实验测到的、连不匹配化合物也有的、rho 为
   0.70 的那种共享背景效应。
2. GDC-0879 是一个真实的、具名的 BRAF 抑制剂。MCF7(乳腺癌)和 PC3
   (前列腺癌)并不像黑色素瘤细胞系那样常规地按 BRAF 突变状态挑选。
   本实验的协议本身,能不能确立 GDC-0879 的负跨细胞系 rho 是由两个细胞系
   之间 BRAF 通路差异造成的?要支持这个具体的因果主张,本协议还需要
   补充什么?

<details data-worked-answer>
<summary>参考答案</summary>

缺失的检查是零假设对照:如果不知道不匹配的化合物在原始数值上也能相关到
约 0.70,单独一个 0.79 就无法与几乎每条谱都共享的背景结构区分开。只有
减去按板匹配的载体对照基线、去掉大部分共享结构之后,一个真实的 rho 才
本身具有信息量。关于 GDC-0879:不能。本协议计算的是相关性,不是机制。
它从未测量 BRAF 通路活性、突变状态,或除了 978 个 landmark 基因表达量
之外的任何其他分子读数。要支持关于 BRAF 的具体因果主张,至少需要在两个
细胞系中都测量基因型或通路活性,而这是本协议没有采集的。

</details>
