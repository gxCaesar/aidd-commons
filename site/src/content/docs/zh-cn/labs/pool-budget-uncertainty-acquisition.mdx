## 运行之前

**模式：阅读既有结果。** 下面的命令读取的是本页所报告的、已经完成的一次运行，
而不是重新跑一遍。产生这里六种既有策略（MaxMin、五个固定随机种子）的那次真实
战役，早已在它自己的一次性守卫下完成，并且保持原样不变。本页在同一份真实划分
与预算之下，加入了第七种策略，在一个单独的一次性守卫下运行一次，写入它自己的
目录。

```bash
python labs/pool_budget/run_uncertainty_campaign.py validate-protocol
python labs/pool_budget/export_uncertainty_summary.py
```

`validate-protocol` 不读取任何检测数据。`export_uncertainty_summary.py` 只是
核对下方已提交的汇总结果是否与本地已完成的运行一致，不执行任何计算。在一个
全新且经过授权的工作区里，则会改为运行一次
`run_uncertainty_campaign.py evaluate-locked --confirm-locked-evaluation`。

## 一种故意不做到"标签盲"的策略

[既有的 pool-budget 契约](/zh-cn/labs/pool-budget-contract-inspection/)读取的
两种策略在打分之前都看不到任何标签：MaxMin 只按化学距离挑选，五个随机种子则
完全不看任何东西挑选。两者都没有把选择与模型自己相信什么联系起来。

这个策略做到了这一点。在四轮中的每一轮，它都会在当前训练集（初始母体分子，
加上本次运行在更早轮次里已经获取的一切）上，按稳定、非随机的方式切分出五个
折叠，分别拟合五个岭回归模型，用全部五个模型预测每个剩余候选，并按五折预测
的方差最大者获取本轮批次。它在本次运行获取某个 pool 标签之前绝不读取它，
并且在每一轮全部敲定之前绝不读取任何评估集标签。这条访问规则由
`pool_budget_uncertainty.py` 中的 `AcquiredLabelLedger` 在代码层面强制执行，
不仅仅是文字上的声明。

**这是一个排序信号，不是一个经过核验的校准区间。** 跨折叠方差只用来给候选
排序；这里没有检查它是否是一个校准过的预测区间，例如通过在留出标签上核对
区间覆盖率。

## 观测结果

以下数值于 2026-09-11 在一台 Apple arm64 机器上，用 Python 3.11.15、NumPy
2.4.6、RDKit 2025.9.6 与 scikit-learn 1.9.0 计算，沿用已完成战役早已固定的
那份真实划分与预算：

| 检测                      | 不确定性 AUC | MaxMin AUC | 5 个随机种子中最好 | 5 个随机种子中最差 |
| ------------------------- | -----------: | ---------: | -----------------: | -----------------: |
| CHEMBL5736995（主检测）   |       0.1133 |     0.0508 |             0.1016 |             0.0762 |
| CHEMBL3705421（另一检测） |       0.1635 |     0.0000 |             0.1058 |             0.0096 |

在这一次确定性运行中，不确定性策略在两个检测上都领先于每一种既有策略。这只是
在一个已声明折叠数下的单次重放；没有尝试并比较过别的折叠数，这也不是"它总会赢"
的主张。

## 这没有展示什么

这只是一个新策略在一个折叠数、一个集成规模下的一次确定性运行，不是一次扫描。
它沿用了冻结契约里早已声明的同一个岭回归惩罚项，而不是为这个策略单独调参，
因此这里的领先并不能证明那个惩罚项本身是经过校准的。正如已完成战役自己的
契约已经披露的那样，这份 pool-budget 材料在那项独立的表示研究自己的评估运行
之前，就接触过与之共享的标签；本次运行继承了同一条已披露的暴露，仍然只是
回顾性教学，不是标签未见的发现，也不是前瞻性主张。

## 独立练习

一位同事提议只报告主检测的 0.1133 这个 AUC 作为"这个策略"的结果，理由是它是
两个检测中数值较大的那个。

1. 说出另一检测的骨架多样性列（第一轮之后每个检查点都是 `1.0`）告诉了你什么，
   而主检测的对应列没有告诉你。
2. 为什么把某一个检测的数字报告成"这个"结果，会让读者少了解一些本该用来判断
   这个策略的信息？

<details data-worked-answer>
<summary>参考答案</summary>

另一检测的 pool 只有一个骨架分组，所以它的骨架分数列从第一轮起就是 `1.0`，
这是那个 pool 结构本身的事实，不是策略追求多样性的证据；一个对多样性毫无
追求的策略在那里也会显示同样的列。只报告一个数字，掩盖了两个检测在"一个被
恢复的目标"或"一次多样化的选择"到底意味着什么上的巨大差异：不同的 pool 规模、
不同的骨架数量，以及正如姊妹协议已经说明的，pchembl_value 作为活性度量的
可靠性也不同。两个检测是两个单位，一个在两者上都领先的策略，比一个只在你
选择报告的那一个上领先的策略，证据更强。

</details>
