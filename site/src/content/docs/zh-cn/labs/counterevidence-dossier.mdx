## 运行之前

**模式：对已提交文件做可运行的检查。** 该命令读取本仓库已经分发的八份已完成实验产物。
它不发起网络请求、不拟合任何东西、不重跑任何实验。它无法告诉你任何结果是否正确。
它回答的是另一个问题：**这个项目保留了哪些"不留会更好看"的东西？**

```bash
python labs/counterevidence/inspect_dossier.py show
```

一份提名档案是靠它保留了什么来判断的。有六类反证会被压进同一段"局限性"里，
然后悄悄消失，所以这条命令把它们分开：一项已在协议中声明却被有意不执行的评估、
一个跑了并且输给自家基线的方法、一个被拒绝填写而不是被填上数字的指标、
一句缩小主张适用范围的披露、一处对自身记录缺口的承认，
以及被保留下来而不是被平均掉的测量离散。

每一类对应的修复动作都不同。把它们混为一谈，正是一份档案最终写着"存在一些局限"
却什么也没说的原因。

## 1. 在迁移上失败的那个赢家

这是本仓库里最锋利的一件产物，而它之所以还在，只因为两个比较都被报告了。

在骨架互斥的主测试上，覆盖 132 个母体化合物，Morgan 指纹 ridge 模型误差三者最低：
0.41833032711934154，对比训练均值基线的 0.47889315075040634。
在测定复现上，覆盖 170 个母体，**同一个模型是三者中最差的**：
3.1316760122202343，对比基线的 0.898379755056597。它的秩相关从主测试上的正值
翻成复现上的负值，为 -0.04095526286121213。

命令会重算这个比值而不是照抄：在复现上，那个"获胜"的模型带着基线 3.49 倍的误差。
**只报主测试会是真话，同时也是误导**，而这正是唯一要紧的组合。
产物里也用文字写明了这一点，并有一项检查确认那句话还在。

## 2. 出现在双方记录里的那句披露

一个实验在另一个实验评估开始之前，接触过与之共享的标签。这次接触被记录在**两份**产物里：
被接触方，以及造成接触的一方。

这正是"虽然诚实但容易做错"的地方。单边披露——只由结果被削弱的那一方记录——
会让另一个实验看上去是独立的，而它并不是。检查要求两边都有。

## 3. 被拒绝填写、而不是被填上数字的那个指标

三个基线相关系数被存成 `null`，状态为 `undefined_constant_prediction`。
常数预测没有秩相关，因此根本没有数字可报。

在那里写 `0` 是很诱人的做法，而它会凭空造出一个基线根本进不去的比较——
读者会看到一个模型在某个指标上"赢过"了一个从未拥有该指标的基线。
两项独立的检查覆盖这一点：一项确认状态仍是 undefined，
另一项确认存的值仍是 `null`，从而没有任何后续算术能把它吃进去。

## 4. 核对反证是否还在

```bash
python labs/counterevidence/inspect_dossier.py check
```

共十三项检查。它们确认八份产物全部可解析，其中六份至少带有一句披露；
确认迁移失败仍以同一方向、同一量级重算得出；确认七项已声明的评估仍被记为未运行
而不是被略去；确认在两次回放中，被设计的获取策略仍低于全部随机实例，
且其中一次一个目标都没有回收到；并确认每一句提到 p 值或置信区间的话
都是彻底拒绝报告它们，而不是在报告它们。

这些检查核实的是**反证仍然存在、并且仍然是各课引用的那句话**。
它们不核实任何结果是否正确，这里也没有任何一项检查能做到。

## 独立练习

你接手了一份候选物的档案。它的摘要写着："模型性能已在留出测试集上验证（MAE 0.42）。
存在一些局限，仍需进一步工作。"

请用上面六个类别说明这句话分辨不了什么，并说出你会先问的那一个问题。

<details data-worked-answer>
<summary>参考答案 —— 一句话里的六次坍缩，以及第一个问题</summary>

**"已验证"掩盖了"未运行"这一类。** 一份协议通常声明了好几项评估，这句话只提了一项。
它无法告诉你其余各项是跑了但被扣下、跑了但输了、还是声明了却从未执行。
这是三份不同的档案，而只有第三种在不加解释的情况下站得住。

**单独一个 MAE 掩盖了"负结果"这一类。** 你拿到的是某一个比较的数字。
如果存在第二个比较且模型在那里输了，这个事实恰好落在这句话什么也没有的位置上。
本仓库自己的产物就是现成的例子：同一个模型，一个比较上是 0.41833032711934154，
另一个比较上是 3.1316760122202343。

**"留出测试集"掩盖了"被拒绝的指标"这一类。** 它没有说明哪些指标是可计算的。
一个返回"未定义"、随后被填上一个看似合理的零的指标，从外面看，
与一个真正被测量出来的指标完全一样。

**"存在一些局限"就是被抽掉了内容的"适用范围限制"这一类。**
一句范围限制只有在说明了"这个结果不可用于什么"时才有用。没有那一半，
它不传递任何信息，只起免责声明的作用。

**这里没有任何东西属于"自身记录缺口"这一类。** 一处对自身记录缺口的承认——
未被保留的预测、日志丢失的一次运行——无法从摘要里推断出来。
它只能被主动交代，而人们几乎从不交代。

**这里也没有任何东西属于"保留的测量离散"这一类。**
如果同一个化合物的重复测量彼此不一致，那么聚合规则决定了这份不一致
有多少能活着进入你拿到的那个数字。

**第一个问题。** 不是"它是怎么验证的"——那只会换来同一句话的加长版。
要问：**"协议一共声明了哪些评估，每一项现在处于什么状态？"**
它可以由"要么存在、要么不存在"的记录来回答，一步就把"未运行"和"输了并被扣下"分开；
而一份答不上这个问题的档案，已经把你需要知道的告诉你了。

</details>

## 它不做什么

这条路径不重跑、不重调、不重采样任何已完成的评估，也不核对某个结果是否正确。
它读的是已复核的摘要，并重算这些摘要中已有数字之间的关系。它的权威性恰好等于那些产物的
权威性，而每一份都带着自己的协议与复核日期。

这些产物本身就是各个实验：
[ChEMBL EGFR 表示基线](/zh-cn/labs/chembl-egfr-representation-baselines/)、
[rMD17 能量基线](/zh-cn/labs/rmd17-system-state-energy-baselines/)、
[池预算实验](/zh-cn/labs/pool-budget-campaign/)与
[FreeSolv 诚实基线](/zh-cn/labs/freesolv-honest-baselines/)。
它们背后的契约见
[ChEMBL 契约检查](/zh-cn/labs/chembl-contract-inspection/)。
更广的论证见
[反证与失败分析](/zh-cn/learn/candidate-nomination/evidence-to-validation/)。
