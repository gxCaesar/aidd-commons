## 学习目标与先修

经典力场预先固定能量面的函数形式,再拟合它的参数。机器学习原子间势让模型从数据里学出这个能量面。
这一次替换就是全部要点,也正是全部难度:经典力场在自己的文档里写明含有哪些项、拟合了什么;
学出来的能量面则继承产生它的那个语料库的覆盖范围,而恰恰是这部分语料库,各份发布在记录方式上
差别最大。

先读[力场与采样](../force-fields-and-sampling/),它固定经典力场的契约;再读
[物理模型与体系状态](../physical-model-system-state/),它固定体系状态是什么,以及为什么一条轨迹里的
若干帧不是彼此独立的观测。

读完你应当能够就任何一份已发表的原子间势说明:读者能不能跑通发布的代码、能不能重训发布的模型、
能不能检视模型训练所用的语料库。这是三个不同的问题,而这些公开产物对它们的回答并不相同。

## 从固定的函数形式到学出来的能量面

固定的力场预先声明自己的函数形式。读者可以读那条方程、数出项数、看出哪些物理效应是被有意略去的。
力场里没有任何东西被数据藏起来。

学出来的势把那条方程换成一个模型,而模型在未见过的构型上的行为由它见过的数据决定。这个模型通常
被描述成原子图上的一个网络并带有一个声明的等变性,而等变性确实是架构的一个可检验的性质。
但模型在训练分布之外的化学上会怎样,根本不是架构的性质,它是语料库的性质;而语料库正是这些发布
在记录方式上最不一致的那一部分。

对读者而言,可核查的内容随之改变。问一个力场是不是好的近似,是问它的项够不够用;
问一个学出来的势是不是好的近似,是问它的语料库含不含那种化学,以及这份语料库能不能被检视。

## 六份发布的代码库各是什么

目录为这条轨道登记了六份公开发布。这里不给它们排名,因为记录里没有同一协议下的比较。
以下每一项是什么,均取自各自的记录。

**NequIP** 是一个用于构建 E(3) 等变机器学习原子间势的代码库,并通过自己的模型站点分发预训练基础势。
**MACE** 是一个采用高阶等变消息传递的机器学习原子间势代码库,发布面向材料与分子的预训练势,其中一部分
权重带学术源许可。**CHGNet** 是一个面向电荷感知原子istic建模的预训练图神经网络势,训练于 Materials
Project 的弛豫轨迹,用于预测能量、力、应力与磁化。**MatterSim** 是一个作为机器学习力场覆盖整个周期表的
深度学习原子istic模型,发布时附两个预训练检查点、一个微调脚本与一份模型卡。**SevenNet** 是一个图神经网络
原子间势包,带预训练通用势与微调接口,可通过 ASE 计算器与 LAMMPS 使用。**TorchANI** 是一个用于构建、
训练与运行 ANI 式神经网络原子间势的 PyTorch 库,其预训练 ANI-2x 权重发布在 Hugging Face Hub 上。

六份都是真实、可检视的产物,且都有源代码许可:NequIP、MACE、MatterSim 与 TorchANI 为 MIT,CHGNet 为
BSD-3-Clause,SevenNet 为 MIT。其中四份另行发布了带记录所载许可的权重,且有两份的权重与代码适用的是
不同且更严格的许可。

## 六份记录的开放性图景

目录把七个开放性维度分开记录,正是为了这一点。横着读六份记录,规律很清楚。

| 维度 | 可得 | 未核实 |
| --- | ---: | ---: |
| 推理代码 | 6 | 0 |
| 训练代码 | 6 | 0 |
| 架构 | 6 | 0 |
| 权重 | 4 | 2 |
| 训练数据 | 2 | 4 |
| 数据配方 | 0 | 6 |
| 评测代码 | 1 | 5 |

推理、训练与架构在六份里全部可得。权重在六份中的四份可得,两个例外是 CHGNet 与 SevenNet,
它们的记录说明:即使仓库就在许可文件旁边,所打开的任何页面都没有给出已发布检查点的许可。

最下面两行是读者无法靠推断补上的。数据配方在六份记录里全部未核实。评测代码只有一份可得,即 MACE,
另外五份未核实。一个仓库可以带着训练模型的脚本,却不带训练集如何组装出来的记录。

## 训练语料库在哪里仍是暗的

训练数据在六份中的两份可得。MACE 的记录支持 MACE-MP 检查点的这一主张,其 README 把训练语料库
写为从 Materials Project 弛豫轨迹中选出的 MPtrj。CHGNet 的记录支持 MPtrj 语料库,模型卡记录了
9-0.5-0.5 的训练、验证与测试划分。

另外四份把它留作未核实,而理由的差别很重要。NequIP 的基础势先在 OMat24 上预训练,再在 Alexandria
的一个子样本与 MPtrj 上微调,而没有任何打开过的页面说明该子样本的再分发条款。MatterSim 的 README
只把语料库描述为通过其论文引入的工作流生成的数据,模型卡列出取自 MPtrj 与 Alexandria 的测试集,
却未给出 Alexandria 子集的再分发条款。SevenNet 的文档以 mpa、matpes_r2scan、omol25_low、oc20、
oc22、odac23 这样的任务标签点名 15 个从头计算数据集,这给出了一个选择,却没有描述这个选择是怎么
做出的。TorchANI 内置数据集登记表把 ANI-2x 语料库的 DOI 与文章记作 TODO。

NequIP 的 MP 模型背后的 Zenodo 记录说明:这些模型仅在约 1.5 million 帧的 MPtrj 上训练,并建议用于
基准测试而非生产用途。这是一条关于语料库规模的有用陈述,但它不是关于那 1.5 million 帧里含有什么化学
的陈述。

## 当一个名字指两样东西

有两样资产共用 OMat24 这个名字,而它们带不同的许可。在 Hugging Face Hub 上,OMat24 数据集被标为
cc-by-4.0;同一机构发布的 OMat24 检查点集合则被标为 other,并带一份内含 FAIR 可接受使用政策的
专有 OMat24 许可。

这不是吹毛求疵的区别。看到训练描述里写"OMat24"的读者,无法从名字判断指的是哪一个,而两者的条款
并不相同。NequIP 与 SevenNet 的记录都点到了这件事,也都提到微调语料库是 Alexandria 的一个子样本,
而没有任何打开过的页面说明它的再分发条款。

另有两个名字带着类似的风险。MACE 的 README 为其非 MP 检查点点名 OMAT、OMOL、MATPES 与 SPICE
语料库,却不说明它们的许可。MatterSim 则把更高级的预训练版本与更多材料能力放在一个托管产品里,
其页面不说明许可。

## 当两个结果并不独立

SevenNet 自己的 README 说明其核心模型基于 NequIP。因此归于 SevenNet 的结果与归于 NequIP 的结果
并不是在测两个独立架构,而把两者当成排行榜里两个独立条目的比较,读的是一棵家族树而非一个样本。

同样的问题适用于微调语料库。当一个架构在另一个架构预训练所用的语料库上微调时,两者在所覆盖的化学
上并不独立,无论架构如何。

## 一个报告出来的误差意味着什么,又不意味着什么

各记录对自己的页面所报数字都很谨慎,这些提醒值得带进任何比较。

CHGNet 模型卡报告了在其 MPtrj 测试划分上能量、力、应力与磁化的平均绝对误差,记录同时指出:复核期间
没有打开这篇文章的出版方页面,所以引用是按 README 的说法记录的,而不是取自文章本身。MACE 的 README
说明 MACE-MP 模型训练于来自 VASP 输出的 MPtrj 原始 DFT 能量,与带 MP2020Compatibility 修正的
Materials Project 能量或 CHGNet 能量不可直接比较。SevenNet 文档报告 WBM 数据集上的 F1 与 RMSD
以及一个综合性能分,但打开过的页面既没有给出指标定义,也没有给出评测代码。

因此同一个指标上的两个结果并不是两次测量。标签不同,而说明这一点的记录,恰恰也是那五个把评测代码
留作未核实的记录之一。从模型卡引来的误差,是一个读者可能拿不到其协议的数字。

## 一次有协议的比较需要什么

对这些发布做排名的比较需要三样记录目前没有的东西。它需要一条所有模型都跑过的评测代码路径,
因为六份里有五份把评测代码留作未核实。它需要一份声明的划分与一份声明的指标定义,因为所报误差用的是
不同语料库、不同标签,而在综合性能分那个例子里,还是一个未定义的聚合。它还需要训练语料库的条款,
因为语料库无法再分发的模型,无法被一个本就不在权利人内部的读者重训。

记录今天支持的是关于每份产物发布了什么的陈述。这与排名是不同的话,而且它是读者真正能据以行动的那一句。

## 已解案例

读者想知道 NequIP 的基础势能否被项目之外的人复现。记录分三部分回答。

代码可以取得。推理代码、训练代码与架构全部可得,NequIP 的 Python 包为 MIT。

权重可以取得。模型站点上列出的基础势包带 CC-BY-4.0,Zenodo 记录给出模型产物的 DOI。
有一处细节值得往下带,因为它说明许可字段不说明什么:模型站点的列表给模型包一个许可字段,并不把代码条款
与权重条款分开,所以目录里记录的 MIT 条款来自仓库的许可文件,而不是来自这个列表。

训练无法复现。数据配方未核实,语料库被描述为 OMat24,并在 Alexandria 的一个子样本与 MPtrj 上微调,
而没有任何打开过的页面说明该子样本的再分发条款。Zenodo 记录给出了帧数,并说明这些模型建议用于基准
测试,这告诉读者有多少数据,而不是数据里有什么。

于是读者的问题得到这样的回答:发布的势可以跑、可以看,而产生它们的训练无法依据已公开的内容重复。

## 独立练习

   与数据配方的计数,并说明两个计数之差对想重训而不只是想运行的读者意味着什么。

## 这份材料不说明什么

这篇阅读不做这六份发布之间的比较,也不给它们排名。记录里没有同一协议下的评测,任何次序都只是
哪一页先被读到的产物。

它不说明某个学出来的势是准确的,也不说明它比力场更准。它报告每份发布公开了什么、每份留下了什么
未核实。

它不说明这些训练语料库是小的、有偏的或均衡的。记录里唯一给出规模的语料库约 1.5 million 帧,
而帧数不是对化学内容的描述。

它不告诉你某个权重因为许可没写就不可用。它告诉你条款未知,那是另一个问题,也有另一个解法。
