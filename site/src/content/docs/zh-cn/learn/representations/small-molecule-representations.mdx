**表示并不等同于分子。**它是化学实体的一种已声明的计算视图。每种视图都会保留某些区分、移除其他区分，并增加实现选择。因此，更大的嵌入并不自动更具信息量，合法的字符串也不自动就是正确的科学对象。

本章从化学身份出发，建立通向固定表示和学习式表示的决策框架。现有两个仅用 CPU 的实验室配套实验：一个无标签身份检查器，以及一个冻结的 ChEMBL 37 EGFR 比较，其开发预检和配对评估均已完成。各自的摘要分别保留开发选择、主要性能和失败的 Morgan 检测迁移。

## 前置知识

你应能够读懂常见的键、电荷、芳香性和立体化学记法；区分检测测量与分子；并解释训练/验证/评估划分。如果这些边界尚不熟悉，请复习[数据契约](/zh-cn/learn/data-governance/data-contracts/)和[科学机器学习](/zh-cn/learn/machine-learning/scientific-computing/)。只有在完成配套实验时才需要 Python。

## 学习目标

完成本章后，你应能够：

1. 定义一行数据表示的是母体结构、盐、混合物、质子异构体、互变异构体、立体异构体、构象，还是被检测的物质；
2. 说明 SMILES、InChI、描述符、指纹、图、token 序列和 3D 输入分别保留和折叠什么信息；
3. 根据终点依赖关系而非模型流行度，选择最小充分表示；
4. 构建匹配的描述符与指纹基线，且不允许预处理或实体泄漏；
5. 在信任分数前，审查立体化学、质子化、互变异构、构象、哈希和适用域失败。

## 科学假设

### 化学身份先于特征化

“一种化合物”不是完整的单位定义。一个数据库记录可能含有多个不相连的组分、显式带电状态、未指明的立体中心、特定同位素体，或为某一个构象生成的一组坐标。移除抗衡离子、中和电荷、选择规范互变异构体或丢弃立体化学，都会改变记录之间的等价关系。这些操作可以是恰当的，但前提是先声明预期预测单位。

解析也不等于标准化。工具包可以接受一个 SMILES 字符串、构建图、检查价态、分配芳香性，并输出规范 SMILES，但这并不意味着它已判定两种盐形式或两种质子化状态是同一个实验实体。RDKit 在其 [MolStandardize API](https://www.rdkit.org/docs/cppapi/namespaceRDKit_1_1MolStandardize.html) 中分别公开了片段、电荷、同位素、立体化学和互变异构体母体操作。这种分离应在数据管线中保持可见。

### 终点决定所需分辨率

对于某些整体分子性质，只有连接关系的视图可能足以形成有用的基线。但它本身无法编码检测 pH、溶剂化环境、蛋白状态、结合构象或构象分布。单个 3D 构象包含坐标，却仍不代表构象集合，也不能证明这些坐标与检测相关。反之，为每个任务生成构象可能引入计算量和方法方差，却不增加与终点相关的信息。

在选择特征之前，写下依赖性假设：

- **身份或注册表关联：**保留结构记录和合适的标识符；不要以学习得到的嵌入替代实体解析。
- **局部结构–活性关系：**从圆形指纹或局部图表示开始。
- **整体大小、极性或柔性趋势：**从一个小型且已声明的描述符向量开始。
- **量子能量或力：**坐标、元素、状态和物理对称性是承重信息。
- **蛋白–配体几何：**配体状态、构象或结合姿势、靶标构建体和相互作用上下文都是输入的一部分。

### 不变性是一项科学假设

分子性质的期望输出通常不应在原子索引置换时改变。能量应对刚性平移和旋转不变，而预测的力会随坐标变换。消息传递图、几何网络和数据增强实现了这些假设的不同版本。它们都不会自动提供对互变异构、质子化、立体化学、检测或批次变化的不变性。

### 学习式表示继承其训练历史

预训练分子编码器不是对化学的中性压缩。它的 tokenizer 或图特征、预训练语料、标准化规则、目标、负采样、构象生成和池化方式，决定了它能够学习哪些区分。仅有公开权重并不能确立训练数据契约或其对新终点的适用性。只有在实体集、标签、划分、选择规则和廉价基线固定后，才能比较学习式编码器。

## 表示家族

这些家族是互补的。一个生产管线通常会保留来源记录和标识符以供追溯、固定表示作为基线，以及任务特异的学习式表示。不要把这些角色折叠为一个名为 `features` 的数组。

### 结构记录、SMILES 和标识符

[OpenSMILES specification source](https://github.com/opensmiles/OpenSMILES/blob/master/opensmiles.asciidoc) 定义了 SMILES 行语言的一种开放形式。多个有效 SMILES 可以遍历同一个分子图。“Canonical SMILES”表示某个特定算法和版本选择了一种确定性序列化。RDKit 在其 [Python guide](https://www.rdkit.org/docs/GettingStartedInPython.html) 中通过将多个吡啶字符串映射到一个工具包规范输出展示了这一点。RDKit 还记录了规范输出发生变化的版本，因此工具包和版本属于契约的一部分。

异构 SMILES 可以编码四面体和双键立体化学；非异构输出会刻意移除这些区分。未指定的立体化学不是外消旋体、单一对映体或任意指定中心的证据。以点分隔的 SMILES 表示不相连的组分。若没有来源记录和整理规则，不能安全地假定最大组分就是被检测的材料。

[Standard InChI](https://iupac.org/who-we-are/divisions/division-details/inchi/) 对连接关系、氢、电荷、立体化学和同位素使用受治理的层。InChIKey 是一种适合索引的定长衍生物。没有查找关系时，无法将它解码回结构。应使用它检验和记录身份假设，而非将其作为具有化学意义的数值特征。

[SELFIES](https://doi.org/10.1088/2632-2153/aba947) 约束分子字符串，使生成的 token 序列在其语义规则下映射为有效分子图。这种鲁棒性处理无效字符串生成，却不能保证唯一性、类药性、可合成性、预期的质子化状态或生物活性。

### 固定描述符

描述符将分子对象转换为已声明的标量。示例包括分子量、原子或环计数、形式电荷、Wildman–Crippen logP、拓扑极性表面积、氢键供体和受体计数，以及可旋转键。[RDKit descriptor guide](https://www.rdkit.org/docs/GettingStartedInPython.html#descriptor-calculation) 公开了这些计算，而 [RDKit Book](https://www.rdkit.org/docs/RDKit_Book.html#implementation-of-the-tpsa-descriptor) 记录了一个重要实现细节：其默认 TPSA 会省略硫和磷的贡献，除非某个选项要求纳入它们。

这说明了正确的解释方式。一个描述符名称不是完整定义。记录工具包版本、参数、氢处理、标准化输入对象、缺失值策略和仅训练集缩放。检查训练数据上的常量和近常量列。当数据集较小时，描述符基线尤其有用，因为它揭示了大部分可学习信号是否已经由简单的大小和组成解释。

### 指纹和相似度

指纹并非一种表示。基于预定义结构键（key）的指纹标记固定模式词典。路径和拓扑扭转指纹枚举键路径。原子对指纹组合类型化原子和拓扑距离。药效团指纹抽象出供体、受体、芳香基团及其间隔等特征。圆形指纹扩展局部原子环境。

Morgan/ECFP 风格的指纹迭代地编码原子周围的邻域。奠基性的[扩展连接指纹论文](https://doi.org/10.1021/ci100050t)为分子表征和结构–活性建模开发了圆形特征。一次实现仍需要作出选择：

- 原子不变量或特征类别；
- 半径，其中半径为二时覆盖每个中心至多两个键的环境；
- 立体化学信息；
- 稀疏标识符，还是经过哈希的计数或 bit 向量；
- 向量宽度和计数模拟；
- 相似度函数。

对于二元向量，Tanimoto 相似度通常为 `c / (a + b - c)`，其中 `a` 和 `b` 是占用 bit 计数，`c` 是它们的交集。高值表示在该指纹契约下的相似性，而不是等价化学或等价活性。将不同环境哈希到同一位置会造成碰撞。bit 向量也会丢失重复特征计数。因此，[RDKit fingerprint documentation](https://www.rdkit.org/docs/RDKit_Book.html#additional-information-about-the-fingerprints) 区分稀疏计数、哈希计数和显式 bit，而不将 “Morgan” 视为完整配置。

### 分子图

2D 图通常将原子映射为节点，将键映射为边。节点特征可以包括原子序数、形式电荷、芳香性、杂化、氢计数、手性和环成员资格。边特征可以包括键类型、共轭性、环成员资格和立体化学。每个被省略的特征都声明了一种不变性或信息损失。

[Message Passing Neural Networks](https://proceedings.mlr.press/v70/gilmer17a.html) 提供了一个常见框架，其中节点通过边交换消息，而读出会聚合图。网络可以学习任务特异的特征，却无法恢复图中不存在的变量。作为不同图输入的两种质子化状态仍是不同示例；在没有立体特征时输入的两个立体异构体可能无法区分。

图大小和邻域深度也很重要。固定次数的消息传递步骤限制了在读出之前信息能够传播的距离。添加虚拟节点、全局描述符、长程边或 3D 距离，会改变表示契约，而不只是改变架构。

### 字符串和学习式序列表示

SMILES 模型看到的是一种序列化。字符、正则表达式、原子级和子词 tokenizer 产生不同的词汇表和序列长度。规范字符串移除了由一个工具包选择的遍历变化；随机化 SMILES 公开同一个图的多种遍历。这些遍历可以是有用的数据增强，却不是新分子或新的独立证据。

公平的字符串模型比较会冻结规范化、立体化学、tokenizer 训练数据、词汇表、最大长度、截断，以及聚合多个字符串的规则。检查同一分子的替代字符串是否跨越划分。否则，任务可能变成字符串识别，而非化学泛化。

### 3D 坐标和构象集合

3D 输入需要的不只是笛卡尔坐标。记录质子化和互变异构状态、显式氢、构象生成器及版本、随机种子、尝试次数、剪枝阈值、能量模型、最小化、保留构象和聚合规则。RDKit 的 [ETKDG documentation](https://www.rdkit.org/docs/RDKit_Book.html#conformer-generation) 描述了距离几何如何与实验导出的扭转偏好结合，并公开了如 `randomSeed` 等可复现性控制。

几何感知模型应编码所需的对称性。[SchNet](https://papers.nips.cc/paper/2017/hash/303ed4c69846ab36c2904d3ba8573050-Abstract.html) 对原子位置使用连续滤波器处理分子能量和力。这是坐标可能是物理终点承重信息的恰当证据。它不是一个生成的配体构象会改善每个生物活性任务的证据。

对于柔性配体，构象集合可能是恰当的输入对象。模型随后必须池化构象、整合预测的构象分布，或作出状态特异的预测。在观察标签后报告得分最高的构象属于结果泄漏。应将构象视为嵌套在一个分子中的重复视图，而不是独立分子。

### 预训练和混合表示

学习式表示包括图编码器、化学语言模型、3D 几何编码器、对比式 2D–3D 模型，以及与文本、蛋白或检测相连的多模态编码器。混合模型可以拼接固定描述符、池化指纹或融合多种视图。它们同时增加容量和假设。

[MoleculeNet paper](https://doi.org/10.1039/C7SC02664A) 在此有用，并非作为永久排行榜，而是作为连接数据集、特征化器、划分和指标的早期匹配框架。现代比较仍需要方案对等、当前实现、用于算法方差的重复随机种子，以及对真实独立化学单位的不确定性。

## 学习式编码器之前的廉价基线

对于冻结的 EGFR 候选，首要决策是固定的全局描述符和局部圆形环境是否携带互补信号。因此基线对为：

1. 一个已声明的 RDKit 描述符向量、仅训练集的缺失值处理和缩放，随后进行 Ridge 回归；
2. 在相同分子、标签、分区、选择指标和正则化选择规则下，使用一个已声明且考虑手性的 Morgan 表示进行 Ridge 回归。

在打开锁定评估前，必须冻结确切描述符列表、指纹形式和正则化网格。在匹配比较、训练均值对照、数据噪声和实现方差显示出与决策相关的余量之前，不应添加深度编码器。若后来评估学习式模型，在保持数据集和协议固定的情况下改变表示；随后在保持表示固定的情况下改变学习器。否则，任何差异的来源都无法识别。

对于分类，一个类似的廉价模型是在相同固定特征上的逻辑回归，且先声明类别阈值、不平衡处理、校准和选择指标。当局部类似物是预期证据时，最近邻或相似度检索是有用的非参数对照。

## 实例：一个结构，多个计算对象

[无标签表示检查器](/zh-cn/labs/molecule-representation-inspector/) 使用七个编写的示例。从仓库根目录运行它：

```sh
env UV_CACHE_DIR=.cache/uv uv run python labs/molecule_representations/run_lab.py inspect
```

它会写入 `tmp/molecule-representations/report.json`，并记录已安装的 RDKit 版本以及每个指纹选项。检查三种对比：

| 对比                     | 预期观察                                                    | 科学启示                                       |
| ------------------------ | ----------------------------------------------------------- | ---------------------------------------------- |
| Kekule 和芳香吡啶 SMILES | 输入字符串不同；RDKit 输出相同的规范异构 SMILES 和 InChIKey | 字符串相等不等于图身份；规范化受工具包范围约束 |
| 两种已定义的丙氨酸对映体 | 异构 SMILES 和 InChIKey 不同；非异构 SMILES 相同            | 移除立体化学会产生多对一映射                   |
| 乙酸和乙酸钠             | 即使总形式电荷为零，该盐仍是离子性的双组分记录              | 解析不能静默选择母体或质子化状态               |

报告还包含原子和键计数、分子式、形式电荷、已分配和未分配的立体中心计数、存在时的 Bemis–Murcko scaffold、六个固定描述符、占用的 Morgan bit，以及非零 Morgan 计数特征。这些是在记录的软件契约下的确定性观察。它们不是实验测量。

作为敏感性练习，使用 `--ignore-chirality`、另一个 `--morgan-radius` 或另一个 `--morgan-bits` 值重新运行，并比较契约和表示字段。不要将所得视图视为额外分子，或将其作为一种配置对终点预测更佳的证据。

配套的 [ChEMBL 37 EGFR 表示基线实验](/zh-cn/labs/chembl-egfr-representation-baselines/) 随后从身份检查转向匹配的预测比较。它使用 214 个冻结 RDKit 2D 描述符、一个考虑手性的 Morgan 指纹、一个 scaffold 不相交划分、仅训练集预处理和仅验证集 Ridge 选择。其已审阅页面将历史开发数据漏斗与已完成的主要结果和另一项检测的结果分开，包括排名反转，同时不公布分子成员资格或原始 ChEMBL 数据。

## 评估陷阱

### 1. 划分前的实体泄漏

替代 SMILES、盐形式、互变异构体或剥离立体化学的记录，可能将近乎相同或相同的实体置于划分两侧。在特征化前解析并审计实体关系。保留来源记录，以便审查有损的母体映射。

### 2. 表示依赖的分组

Bemis–Murcko scaffold 是由 [Bemis and Murcko](https://pubmed.ncbi.nlm.nih.gov/8709122/) 引入的 2D 骨架定义。它不是自然规律，也不保证前瞻性泛化。无环分子需要显式分组规则。不同的标准化或芳香性选择会改变 scaffold 身份。报告实现，并在划分后检查训练到测试的相似度，而不要默认将分区称为 “OOD”。

### 3. 未匹配的表示比较

同时改变特征、网络容量、增强、预训练数据、调参预算和集成规模，比较的是系统而非表示。使用配对分子和固定分区。为廉价方法提供相同的终点定义和诚实的模型选择预算。

### 4. 在训练外拟合的预处理

描述符插补、缩放、方差过滤、词汇构建、特征选择和学习式 tokenization 都可能检查保留示例。仅在训练集上拟合每个数据依赖变换。诸如已声明指纹的固定化学算法不是“拟合”得到的，但其参数和软件版本仍须冻结。

### 5. 将多个字符串或构象计为独立单位

随机化 SMILES、构象、增强、随机种子、检查点和集成成员是嵌套的计算视图。它们不会增加独立分子、scaffold、检测或化学系列的数量。将它们作为一个实体进行划分，并在已声明的独立单位上聚合不确定性。

### 6. 表示中遗漏终点上下文

生物活性可能随靶标构建体、检测形式、底物、物种、pH 和协议而改变。分子嵌入无法修复汇集不兼容实验的标签。检测感知建模与仅分子预测是不同的输入契约。

### 7. 用置信度替代适用域

狭窄的预测区间或较高的神经置信度，并不能显示查询位于受支持的化学空间内。检查最近的训练类似物、scaffold 或系列覆盖、描述符范围、表示碰撞和检测覆盖。在将预测用于决策前定义弃权规则。

### 8. 将锁定评估重复用于表示选择

在读取测试结果后选择半径、描述符子集、tokenizer、构象策略、预训练检查点或融合权重，会将锁定集转化为验证数据。冻结这些选择，记录选择预算，并只评估最终比较一次。现有的 FreeSolv 实验展示了不同终点的这种分离；其已完成结果不得重新运行或用作 EGFR 结果。

## 失败模式和最廉价的检查

| 失败                                             | 最廉价的决定性检查                                                            | 应对                                       |
| ------------------------------------------------ | ----------------------------------------------------------------------------- | ------------------------------------------ |
| 解析器接受记录，但身份错误                       | 并排渲染来源和解析后的结构；比较分子式、电荷、组分、立体化学和来源 ID         | 在建模前纠正实体契约                       |
| 规范化造成伪重复                                 | 比较来源记录、异构 SMILES、InChI 层和确切的标准化变换                         | 保留模糊关系；不要强行合并                 |
| 立体化学被静默移除                               | 在每次变换前后计数已分配和未分配的立体中心                                    | 保留立体化学，或声明为什么终点对此不变     |
| 盐、互变异构体或质子异构体处理改变每个实体的标签 | 列出多对一映射，以及组内标签不一致性                                          | 重新审视聚合；在需要时保留状态或制剂       |
| 指纹向量饱和或易碰撞                             | 检查占用 bit 比例，并在训练分子上比较稀疏计数与哈希 bit                       | 增加宽度，或仅在冻结的敏感性计划下使用计数 |
| 描述符基线依赖少数大小代理                       | 检查仅训练集的系数、残差，以及按大小和 scaffold 匹配的误差                    | 报告局限；测试互补的局部特征               |
| 图模型无法区分所需状态                           | 构造仅在被省略的节点、边、立体化学或状态特征上不同的配对反例                  | 添加缺失变量或缩小主张                     |
| 3D 结果随构象随机种子改变                        | 在模型拟合前，对同一分子重复构象生成并比较几何导出输入                        | 使用构象集合，或放弃缺乏根据的单构象主张   |
| 预训练嵌入没有匹配增益                           | 在冻结划分下与训练均值、Descriptor Ridge、Morgan Ridge 和仅训练集混合进行比较 | 若增益低于噪声下限，停止添加架构           |
| 外部检测尽管主要改进仍失败                       | 在不对复现重新调参的情况下检查检测定义、实体重叠、校准和残差偏移              | 报告不可迁移性；修改科学问题而不是隐藏它   |

实验性证据优先于表示分数。模型可以排定要测试的对象；它不能把被折叠的化学区分或不兼容的检测转化为有效的机制性结论。

表示工作跨越若干相互独立的法律表面：

- 本课程和原创图形采用 CC BY 4.0，而原创实验代码采用 Apache-2.0；

- ChEMBL 37 数据库内容使用其版本化发布中注明的许可证，而出版商记录和贡献的上游数据可能带有额外署名或复用限制；
- 开源 tokenizer 或特征化器并不使其输入数据集、模型权重或下游预测变为开放。
