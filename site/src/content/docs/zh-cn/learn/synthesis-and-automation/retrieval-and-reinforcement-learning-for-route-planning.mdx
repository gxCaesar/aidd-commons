## 学习目标与前置知识

你将读两个 2026 年发布的路线规划系统，并注意到两者都把工作从"提出一条路线"变成
"在预算内检索一份记忆"。你将读其中一套系统公开的奖励函数——它是一组常数而不是一段
描述——并算出这些常数奖励了什么、又没有奖励什么。你将读另一套系统公开的指标定义与
抽样说明，看清它的标题数字究竟在陈述什么。请先读[反应映射与路线搜索](/zh-cn/learn/synthesis-and-automation/reaction-mapping-and-route-search/)
与[路线可行性、正向预测与反馈](/zh-cn/learn/synthesis-and-automation/route-feasibility-and-feedback/)。
本课是阅读与手算课：本项目没有运行这两个系统，没有合成化合物，也没有执行路线。

## 机制：作为"带预算的检索"的路线

两个系统都把路线规划当作对一份显式记忆的检索，而不是对模型的一次前向传播。在
RetroAgent 中，这份记忆是由一个工具服务器持有的结构化 AND-OR 图；智能体发出工具
调用来扩展这张图，最终返回的路线是搜索真正构造出来的那条路径。在 Agentic-Syn-RRAG
中，工作流被称为 Generate-Retrieve-Refine：本地托管的微调模型通过反应态束搜索提出
候选反应，RXNGraphormer 的嵌入驱动一次 FAISS 检索、取回十个结构上相似的专利先例，
一个重排模型从中选出最相关的三个，随后一个主模型依据这些检索到的证据把提案精化为
一份结构化方案，写明反应物、试剂、溶剂、用量、温度与反应时间。

预算让检索成为一个决策而不是一套流程，而训练与评测都围绕这个预算展开。RetroAgent
公开的奖励值得当作代码而不是散文来读，因为它的常数就是全部规范。完成一条路线的
rollout 获得基础奖励 +1，随后按以下项扣减：超过二十次单步模型调用后每次 0.02 的预算
惩罚，上限 0.3；超过路线深度二十后每步 0.02 的深度惩罚，上限 0.3；每个出现失败工具
调用的 turn 扣 0.05，每个没有可解析工具调用的 turn 再扣 0.05。总奖励被截断在 -1 到 1
之间。未完成路线的 rollout 获得 -1.0；若完全没有产生任何有效工具调用，则为 -1.5。

从这些常数可推出两点，值得带走。第一，预算惩罚只作用在已完成的路线上，因此一次昂贵
的失败与一次廉价的失败得到同样的固定 -1.0。按发布的样子，这个奖励是围绕"成功找到
路线的搜索预算效率"来塑形的，它并不区分"五次调用后失败"的轨迹与"两百次调用后失败"
的轨迹。第二，这些阈值是发布配置的一部分而非实现细节：读者若改动二十这个数、0.02
这个速率或任一上限，就不再运行发布的智能体，已发表的行为也不再描述读者手里的东西。

## 工作案例：两个系统、两种已发表证据

RetroAgent 由一份 README 和一条 COLM 2026 的 BibTeX 条目描述，作者为 Zhu、Gan、Sun、
Sun、Shi、Islam、Shang、Gao、Coley、Sun 与 Wang。README 对方法与训练配方给出了罕见
的细节：策略在 Qwen3-4B-Instruct-2507 基座模型上用强化学习端到端训练，算法为 GSPO
（一种序列级裁剪方法），在 slime 框架内结合 Megatron 与 SGLang，训练与推理依赖由固定
版本的 Docker 镜像提供，硬件是单台八卡 H200 节点、共置模式。README 并不给出路线
质量方面的测量，因此本课不引用它的任何路线准确率。它的开放性也是分层的，每一层各有
条款：仓库代码为 MIT，Hugging Face 上发布的权重为 Apache-2.0，权重仓库把 DESP 来源
的数据标为 CC BY 4.0、SCScore 数据标为 MIT，而 NOTICE 文件说明 `external/desp/` 下
内置的单步逆合成模型源自 Yu 等人的 DESP 工作（NeurIPS 2024），仍受该项目自身的许可
与署名约束。因此仓库上的 MIT 授权并不覆盖这个内置组件，而这里的"开放权重"也不等同于
"整个系统都是 MIT"。

Agentic-Syn-RRAG 由 Shan Zhu、Xin Chen、Pinqi Wang 等十位作者撰写，是 ChemRxiv 预印本
2026 年第 1 版，DOI 为 10.26434/chemrxiv.15008409/v1，代码在仓库
SamSamChu/Agentic-Syn-RRAG 下以 MIT 许可发布。它的 README 报告了自己的数字，而这些
数字更有意思，因为评测协议与数字一并给出。评测集是从 product-disjoint 的 WIPO-2M
留出测试集中随机采样的 150 个目标。在这 150 个目标上、Top-1 条件下，README 报告完整
Syn-RRAG 流程的反应物准确率 48.0%，SFT Llama 基线 46.0%，原生 Gemini-2.5-Pro 14.7%；
规则检查给出有效率 100.0%、元素一致性 100.0%、结构兼容性 99.3%。它另外报告独立的
SFT 骨干在约一万个产物的完整 WIPO-2M 留出测试集上 Top-1/3/5/10 为 44.5%、65.1%、
70.8% 与 75.9%。

该协议有两个特征会改变这些数字的读法。指标是"合并"的：反应物准确率要求在 RDKit
规范化之后，池化的预测反应物与试剂中必须出现每一个参考反应物组分，而这两个字段被
池化在一起，因为模型可能把真正的反应物归到试剂里。而 Top-k 数字是"前缀"：README
说明，从一次完成的 Top-10 运行中取出的 Top-1、Top-3 与 Top-5 是最终池化排序的前缀，
不必等于用更小采样数做的独立运行。把前缀数字与独立运行数字相比的读者，其实在比较两
种不同的流程，而 README 在有人问之前就写明了这一点。

手算值得做，因为百分比把它藏起来了。在 150 个目标上，48.0% 是 72 个目标，46.0% 是
69 个，14.7% 是 22 个（150 分之 22 是 14.67%）。于是完整系统比它自己的 SFT 基线
多对了三个目标，而一个目标值 0.67 个百分点；它比原生模型多对五十个目标。README
没有为这 3 个目标的差距给出置信区间或配对检验，而在单个采样集上 3 个目标的差距本身
并不构成可分离的证据。两个系统也不可直接比较：RetroAgent 在调用预算下检索图记忆，
Syn-RRAG 把方案锚定在检索到的专利先例上，而"引用了先例的方案"与"用更少扩展找到的
路线"不是同一个主张。

最后，这第二套系统的开放性有一处 MIT 许可证看不出来的限制。代码是开放的，但其默认
配置用一个外部模型经 OpenAI 兼容端点驱动重排与方案精化，重排模型默认为
gemini-2.5-flash，并且主模型与重排模型各自需要凭据。复现该系统的读者需要这些端点
及其条款，因此这里的开放仓库不是一个自洽自足的系统。复现训练又是更进一步：README
需要在固定 commit 上给 LLaMA-Factory 打补丁，因为该补丁修改了内部的数据加载、SFT
流程与训练器文件，并且建议使用 Python 3.12、CUDA 12.8 与四块 GPU。

## 备选方案、边界与独立练习

本课没有确立什么的边界很具体。它没有确立任一系统给出的路线是可执行或正确的；路线
是提案，而第二套系统返回的方案是带引证的提案。它没有确立第二套系统的 README 所称
经湿实验确认的三个目标是有代表性的，因为 README 自己把它们描述为一个独立的简短
演示，而不是 150 目标评测集的一部分。它没有确立两个系统之间的比较，因为这里没有人
比较过它们，而且它们优化的东西不同。它也没有确立 RetroAgent 论文大概报告的路线质量
数字，因为本课没有打开那篇论文。

**手工作练习（不可运行、非实证）：** 某路线规划智能体发布的奖励为：完成路线得 +1，
减去超过二十次单步模型调用后每次 0.02、上限 0.3 的预算惩罚；减去超过深度二十后每步
0.02、上限 0.3 的深度惩罚；减去每个失败工具调用的 turn 0.05 与每个无可解析工具调用
的 turn 0.05；结果截断在 -1 到 1 之间；未完成路线为 -1.0，完全没有有效工具调用时为
-1.5。另有一个检索增强的规划器报告：在 150 个目标上 Top-1 反应物准确率 48.0%，其自
身微调基线在同一 150 个目标上为 46.0%，原生通用模型为 14.7%；其指标合并预测反应物
与试剂，其 Top-k 数字取自已完成的 Top-10 排序的前缀。(a) 计算这样一条奖励：路线完成，
45 次单步模型调用，最深路线深度 35，两次失败工具调用。(b) 计算路线完成、20 次调用、
深度 20、无失败工具调用时的奖励，并说明你原本以为哪一项会起作用。(c) 计算一条未完成
路线在 200 次单步模型调用、深度 60 时的奖励，并说明这说明发布的奖励惩罚了什么。(d)
把三个准确率换算成 150 中的计数，算出完整系统与其自身基线之间相差几个目标，并说明在
把这个差距读作可分离之前需要报告什么。(e) 说出合并规则相对于不合并让哪一种情况更容易
得分，并说明合并规则付出了什么代价。

<details data-worked-answer>
<summary>参考答案</summary>

(a) 预算惩罚为 0.02 × (45 − 20) = 0.5，触顶后为 0.3。深度惩罚为
0.02 × (35 − 20) = 0.3，正好在上限。工具惩罚为 2 × 0.05 = 0.10。奖励为
clip(−1, 1, 1.0 − 0.3 − 0.3 − 0.10) = 0.30。(b) 两项惩罚都为零，因为二十次调用与
深度二十恰好是阈值，且没有失败工具调用，所以奖励为 clip(−1, 1, 1.0) = 1.0。你原本
以为会起作用的很可能是最早起作用的那一项，即调用惩罚，而它在二十次调用时根本没起
作用。(c) 未完成路线无论消耗多少预算都是 -1.0，所以 200 次调用与深度 60 都不改变它：
奖励为 -1.0。这是关于发布常数最锋利的一点：预算惩罚施加在已完成的路线上，因此昂贵
的失败与廉价的失败在奖励里无法区分，而"搜索预算效率"这个说法描述的是成功路线上的
行为。(d) 150 个目标中 48.0% 是 72 个，46.0% 是 69 个，14.7% 是 22 个。完整系统比
自身基线多 3 个目标，而一个目标值 0.67 个百分点，它比原生模型多 50 个。在把这 3 个
目标的差距读作可分离之前，报告必须给出在同一批采样目标上的区间或配对检验，并且必须
把比较固定在同一个采样数上，而不是拿某个 Top-10 排序的前缀与别的东西比。(e) 合并让
一个把真正反应物放进试剂里的模型仍被判为正确，这在化学上更公允，代价是分数相对严格
的"只算反应物"规则被抬高；它付出的代价是无法区分"找对了分子"的模型与"搞错了它的角色"
的模型，而且这个数字依赖一个读者在百分比里看不到的字段约定。

</details>
