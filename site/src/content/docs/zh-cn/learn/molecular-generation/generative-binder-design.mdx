英文原文：[Released assets in generative binder design](/learn/molecular-generation/generative-binder-design/)。

## 学习目标与前置知识

学完[流模型与受约束分子搜索](/zh-cn/learn/molecular-generation/flows-and-constrained-search/)后，借这份注明日期的阅读材料把五份结合蛋白设计记录作为发布物检查。完成本课后，你应能说明流水线的哪一部分可用，区分可取得的检查点与完整的训练材料，并指出依赖与许可证据止于何处。

这是一份附有书面练习的来源阅读。本课没有运行模型或流水线、下载权重或下载数据集。记录不提供匹配的比较，因此本课不作性能排名或结合蛋白质量主张。

## 任务约定

这些记录描述不同类型的资产。BindCraft 发布一条流水线，对设计进行过滤，直至达到所要求的通过筛选的候选数量。AlphaProteo 为一个访问受限的模型发布靶点输入准备 notebook。BoltzGen 接收设计规格并返回排序后的候选。RFdiffusion2 为原子层面的支架构建模型发布推理资产。RFD4-Proteina 用配对的流模型与自编码器联合生成序列身份和全原子结构。排序后的候选、已准备的输入与已发布检查点是不同的输出，其中没有一项是实测结合结果。

本课的任务是识别实际发布的资产及其依赖。开放的仓库许可不能自动支配另行获取的模型、未发布的服务或条款未声明的训练数据。

## BindCraft

[BindCraft 仓库](https://github.com/martinpacesa/BindCraft)描述了一条采用 AlphaFold2 反向传播、ProteinMPNN 和 PyRosetta 的结合蛋白设计流水线。其推理流水线与筛选逻辑按覆盖 BindCraft 源码的 [MIT 许可](https://raw.githubusercontent.com/martinpacesa/BindCraft/main/LICENSE)发布。[安装脚本](https://raw.githubusercontent.com/martinpacesa/BindCraft/main/install_bindcraft.sh)下载 AlphaFold2 参数，并从另一个发布渠道安装 PyRosetta。README 称商业用途需要 PyRosetta 许可，对用户提供的 ProteinMPNN 权重则未给出许可。

BindCraft 不发布自己的模型权重，因此流水线记录的权重维度为不适用。这不意味着外部权重或软件对于完整运行是可有可无的。README 描述推理过程，没有给出流水线的训练程序或语料。开放的流水线代码既不确立整套安装的独立授权，也不确立训练复现。

## AlphaProteo

公开的 [AlphaProteo 仓库](https://github.com/google-deepmind/ap_trusted_testers)包含 Trusted Tester Program 的靶点输入准备 notebook，而非模型实现或参数。[公告](https://deepmind.google/discover/blog/alphaproteo-generates-novel-proteins-for-biology-and-health-research/)描述与外部专家分阶段共享，未给出公开的模型下载入口。所打开的公告、[摘要](https://arxiv.org/abs/2409.08022)与仓库文件列表均没有展示已发布的实现、参数、训练代码、训练数据或评估资产。目录中推理代码与权重的不可用条目，记录的是对这些页面检查所得的缺席，而非发布方明确拒绝发布。

该仓库于 2026-08-24 归档。其 Apache 2.0 许可覆盖 notebook 软件，README 则把仓库中的其他材料置于 CC BY 4.0 之下。许可文件仍有未填写的版权占位符，而 README 指明 Google LLC。两种仓库许可都不延伸到未发布的 AlphaProteo 模型。模型访问仍受限。

## BoltzGen

[BoltzGen 仓库](https://github.com/HannesStark/boltzgen)与[检查点模型卡](https://huggingface.co/boltzgen/boltzgen-1)确立了推理代码、训练代码与已发布权重。MIT 条款覆盖其源码和检查点。检查点从另行适用条款的 Boltz-2 基础模型微调而来。已发布的训练归档包含靶点结构、MSA 与小分子字典，但 README 没有说明这些归档的许可。

README 称大型模型还需要今后才会发布的蒸馏数据集。因此，即使训练数据维度标为可用，已发布的训练材料仍不完整。检查点模型卡除指明 Boltz-2 基础模型外，没有描述训练数据。README 还描述自动下载约 6 GB 的 Boltz 材料及约 33 GB 的 ESMFold2 权重与运行环境，并称 ESMFold2 需要兼容 CUDA 13 的 NVIDIA 驱动。这些是仓库所述要求，并非本课执行过的运行。

## RFdiffusion2

[RFdiffusion2 仓库](https://github.com/RosettaCommons/RFdiffusion2)发布一个用于酶与结合蛋白设计的原子层面扩散模型的推理代码。仓库仅支持推理，因此训练代码仍为未核实。权重和容器映像另行托管在 `files.ipd.uw.edu`。其 [BSD 3-Clause 许可](https://raw.githubusercontent.com/RosettaCommons/RFdiffusion2/main/LICENSE.md)覆盖仓库源码，已打开的页面却没有说明权重或映像的条款。

仓库描述了一个从 41 种 M-CSA 酶收集的基准，却没有描述训练语料。[项目文档](https://rosettacommons.github.io/RFdiffusion2/)建议结合蛋白设计使用原始 RFdiffusion。该基准是评估描述，并不证明 RFdiffusion2 在哪些材料上训练，也不证明某项结合蛋白专属的发布主张。

## RFD4-Proteina：识别发布的配对检查点

[RFD4-Proteina 模型卡](https://huggingface.co/nvidia/RFD4-Proteina)指明配套的 `rfd4-proteina-flow-release-2026-10-19` 与 `rfd4-proteina-ae-release-2026-10-19`。自编码器定义流模型使用的潜在表示，因此不兼容版本的组件不能混用。[仓库](https://github.com/RosettaCommons/RFD4-Proteina)提供生成、训练和评分接口。模型卡明确将已发表的效率测量归于 2026-10-09 基准所用的上一对检查点；具名的当前配对没有重做这些测量。每 GPU 小时通过计算筛选的候选也不同于实验确认的结合蛋白。

[已发布训练数据子集](https://huggingface.co/datasets/nvidia/RFD4-Proteina)包含来自 PDB 与 AlphaFold DB 的材料，完整混合数据中的其他组件没有发布。其来源快照日期不能确立通用训练截止日，也不能指明每个检查点使用的组件。[BSD 3-Clause 许可](https://github.com/RosettaCommons/RFD4-Proteina/blob/main/LICENSE)与模型卡覆盖源码和模型权重；新增数据注释与打包采用 CC BY 4.0，上游结构保留自身条款。检查点缺少恢复中断训练所需的优化器与循环状态。联合生成机制与练习见[蛋白质设计前沿课](/zh-cn/learn/biologics-design/frontier-protein-design-2026/)。

访问与许可仍取决于具体资产。BindCraft 的源码许可不解决 PyRosetta 或 ProteinMPNN 的条款。AlphaProteo 的 notebook 许可不覆盖模型。BoltzGen 已发布的训练归档没有声明条款，RFdiffusion2 的代码许可也不解决另行托管的权重或映像条款。

## 训练语料与覆盖范围

| 记录 | 已发表的训练陈述 | 边界 |
| --- | --- | --- |
| BindCraft | README 描述推理流水线 | 未说明流水线训练程序或语料 |
| AlphaProteo | 所检查页面没有公开的训练资产 | 语料与配方未核实 |
| BoltzGen | 归档包含靶点结构、MSA 与小分子字典 | 更多蒸馏数据将来发布，配方未核实 |
| RFdiffusion2 | 仓库描述 41 种 M-CSA 酶的基准 | 基准不是已声明的训练语料 |
| RFD4-Proteina | 来自 PDB 与 AlphaFold DB 的子集及采样元数据 | 完整混合数据与逐检查点组件归属仍不完整 |

归档数量、基准来源或已发布检查点都不能代替准确的训练配方。这些记录没有在共享协议下确立支持某项具体结合蛋白主张的训练材料。

## 推演案例

设一位读者想整理哪些发布物能够独立检查，同时不声称它们能产生有用的结合蛋白。这是构造的资产核查，而非设计程序或实验。

1. BindCraft 允许检查其流水线代码。完整运行还依赖另行获取的 AlphaFold2 参数、PyRosetta 和用户提供的 ProteinMPNN 权重，其条款不在 BindCraft 的 MIT 许可范围内。
2. AlphaProteo 的公开 notebook 允许检查输入准备，却不提供访问受限的模型。它们的 Apache 2.0 与 CC BY 4.0 条款也不授予模型访问权。
3. BoltzGen 有代码和检查点，但已发布训练材料不完整，归档条款未说明，基础模型也有自己的条款。
4. RFdiffusion2 有推理代码和另行托管的权重，但代码许可不确立权重条款，酶基准也不是其训练语料。
5. RFD4-Proteina 有具名的配对检查点和公开训练接口。发布的子集不能重建完整训练混合数据，上一对检查点的基准也不是对当前配对的测量。

由此得到的清单可以描述已发布资产和剩余条件，却不能把这五种不同的发布物变成候选质量比较。

## 独立练习

一位同事说，BindCraft 的 MIT 许可覆盖其安装脚本取得的所有资产，AlphaProteo 的 notebook 仓库证明模型可用，BoltzGen 已发布的归档构成完整训练集，而 RFdiffusion2 的 41 种 M-CSA 酶基准指明其训练语料。请逐项指出这位同事跨过了哪一条资产或证据边界。

BindCraft 的 MIT 许可覆盖其源码，PyRosetta 与用户提供的 ProteinMPNN 权重适用另外的或未说明的条款。AlphaProteo 的 notebook 用于准备输入，而所检查页面没有提供模型实现或参数。BoltzGen 的 README 明确称还有蒸馏数据集待发布，因此现有归档只是部分材料。RFdiffusion2 指明了一项酶基准，却没有描述训练语料。每项说法所需的是另一件资产或另一道过程的证据，并非引用记录已经确立的内容。
