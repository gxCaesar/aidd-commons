## 比较约定

候选池限定可被选择的对象。已获取的观测用于训练代理模型，而采集目标决定如何给
候选对象评分。选择、评分和取得新标签是不同操作。回顾性候选池中的留出标签与
一次新实验的结果具有不同的证据效力。解读活动前，仍须像前面的课程一样声明信息
边界和整数预算。

## 循环中的职责

ALF 在文档中的循环里点名了以下组件。最后一列说明框架提供什么，以及读者需要在
哪里提供科学输入。

| 职责 | 前面课程中的概念 | ALF 组件及提供方 |
| --- | --- | --- |
| 候选数据集 | 合格候选池和已获取的观测须与预留结果分开 | 数据集保存候选对象与已知标签；读者提供任务数据 |
| 概率代理模型 | 只有在可用标签进入训练之后，拟合预测才能用于后续选择 | `Surrogate` 包装选定的模型；已获取的观测提供训练标签 |
| 采集函数 | 目标对候选对象评分；距离、不确定性与效用是不同的量 | `acquisition_fn` 按选定规则给候选对象评分 |
| 搜索函数 | 分数本身不是选出的批次 | `search_fn`（如 `DatasetSearch`）根据采集结果选择候选对象 |
| 优化器 | 选择过程将评分规则与搜索过程结合 | `Optimizer` 连接 `acquisition_fn` 和 `search_fn` |
| Oracle 或评分器 | 只有来源提供标签，反馈才成为观测 | `Oracle` 调用评分器；文档中的评分器使用留出候选池或实时评分器，而真实实验室须由读者提供 |
| 设计任务 | 轮次和批量大小决定反馈何时能改变下一次选择 | `DesignTask` 协调已配置的循环 |
| 状态记录器 | 轨迹记录循环状态，不会把预测变成测量 | `TerminalStateLogger` 等状态记录器在任务运行时记录状态 |

代理模型是循环用来预测尚未观测标签的低成本模型。Oracle 则提供下一个标签的来源。
把留出候选池评分器换成实验室，会改变标签的含义，却不会抹去这两个职责的区别。
同样，采集值是分数，搜索函数才依据分数作出选择。

## ALF

ALF 是用于科学主动学习的模块化框架，提供循环接口，以及现成的数据集、模型和
采集策略。其源码使推断、训练和评估代码被记录为可用。训练代码让读者用观测拟合
代理模型，并不等于预训练模型。框架本身不发布预训练权重。若从其他项目加载代理
模型或 Oracle 模型，还须遵循那些项目自己的许可。ALF README 声明框架和工具包
采用 Apache-2.0。

文档中的 Oracle 对留出候选池评分，或使用实时评分器。记录没有列举具体的实验室
Oracle，因此希望把真实实验纳入循环的读者需要自行提供。记录也没有确立数据可用性
声明、数值基准结果或已报告的案例结果。该记录未打开论文正文，因此本课不引入
其中关于采集策略的比较。

## Mobley Lab notebooks

Mobley Lab active-learning notebooks 发布了配体优化研究所附的流程，其中包括针对
多靶点结合的多目标优化，以及连接结构方法与数据驱动亲和力预测的一项研究。
记录将可获取的 notebook 代码列为推断代码，但没有确立单独可用的训练代码、
预训练权重，或含实验室 Oracle 的完整循环组件。阅读已发布的 notebook 得到的
是可供查看的流程，不是已经执行的结果。

README 没有许可声明，该记录也没有检查仓库的许可文件。因此记录不载有许可，
访问级别仍未核实。README 也没有给出数据集或数据可用性声明，也没有给出运行
任一 notebook 的命令。记录未打开所附论文正文，因此其中报告的改进与比较不构成
本课使用的证据。

## 推演案例

一位读者已有候选池、拟合的代理模型，以及为剩余候选对象评分的采集函数。搜索
函数选中了其中一个。这个循环对该候选对象确立了什么？要取得新的实验标签，
哪项职责必须由真实实验室而非留出候选池承担？ALF 记录是否确立框架随附了
这样的职责实现？

选择只能说明已配置的搜索过程依据已配置的采集分数选中了候选对象。它既不是
测量，也不能证明该化合物值得制备。Oracle 或评分器须连接真实实验室。ALF
记录了留出候选池评分器或实时评分器，却没有列举具体的实验室 Oracle。读者须
自行提供，并按事先声明的方案评估随后得到的观测。本案例不对候选对象的化学
性质作出判断。
