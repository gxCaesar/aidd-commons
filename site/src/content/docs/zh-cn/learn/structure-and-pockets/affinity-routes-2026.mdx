学完[结构、亲和力与预测输出的含义](/learn/structure-and-pockets/structure-affinity-mechanisms/)
和[开放结构预测工具链](/learn/structure-and-pockets/open-structure-stack/)后，
辨别每条路径的输出、内部折叠复合物与输入结构的区别，以及记录中的资产允许读者

## 比较约定

这些记录描述不同的工具，并非在匹配条件下进行的亲和力基准比较。AQAffinity 和
Nesso-1 是学习式预测路径。ByteFF 和 ByteFF2 为分子模拟提供力场参数，并不直接
报告配体是否结合。模拟自由能还需要明确的下游模拟和分析方案。它既不是学习模型
输出的亲和力数值，也不是实验测量。所谓无需输入结构的路径仍可能在内部生成结构。
这意味着读者无需向该路径提供实验复合物结构。

## AQAffinity

AQAffinity 是基于 OpenFold3 主干、无需外部结构输入的亲和力预测模块。它接收
蛋白序列和配体表示，在内部折叠复合物，并在无需输入实验结构的情况下预测亲和力。
仓库设置了访问门槛，提交申请后自动批准。仓库描述提到源码和权重，但记录
无法读取模型卡或仓库文件。因此，推断代码、权重和训练代码均未核实。文件列表
不能证明未经认证的读者可以检查或执行这些资产。

仓库元数据声明 Apache-2.0。由于记录无法读取许可证正文和模型卡，它未能确立
这项授权对代码、权重或附带数据的适用范围。记录也未确立检查点名称、训练数据
构建方式、输出约定或论文标识符。资源描述依据项目公开元数据，而非已读取的模型卡。

### 公开结构检查点不能指明亲和力预测模块

另行建立的 `model-openfold3-openbind0` 记录于 2026-10-25 核查，指明公开的 OpenBind-0 结构检查点。[OpenFold3 参数参考](https://openfold-3.readthedocs.io/en/latest/parameters_reference.html)将它设为软件包 `0.5.0` 起的默认参数，PDB 训练截止日为 `2025-06-30`。这些参数预测结构，并不指明或发布 AQAffinity 训练过的亲和力预测模块。[OpenBind-0 发布分析](https://openbind.uk/news/blog-openbind-0-advancing-open-molecular-structure-prediction/)与[共折叠版本练习](/zh-cn/learn/structure-and-pockets/cofolding-frontier/)还区分软件包、检查点与化学引导选择。因此，结构主干公开不能填补 AQAffinity 的未核实字段，也不能消除其访问门槛。若同事声称下载 OpenBind-0 就能执行 AQAffinity 亲和力预测，缺失的证据是兼容的亲和力模块检查点、其输入输出约定，以及它自己的访问和许可条款。本课没有运行这项预测。

## Nesso-1

Nesso-1 在 token 层面共同折叠蛋白与配体的粗粒度表示，不使用 MSA 模块或重原子
生成模块。它接收蛋白序列以及 SMILES、CCD 编码或 SDF 格式的配体，输出亲和力
数值和结合体概率。记录确立了推断代码、评估代码和已发布的权重，训练代码仍未核实。
README 完全没有说明训练数据，因此无法从本记录得知训练数据集或数据配方。
记录没有打开所链接技术报告的正文，因此不承载其中报告的准确度或速度结果。

README 和模型卡声明 Apache-2.0 适用于源码及已发布权重。权重页面既没有给出
检查点名称，也没有给出下载命令，所以发布权重不等于指明可运行的检查点。加速
内核要求 CUDA 12，其他环境应使用默认安装或 `--no_kernels`。页面没有确立亲和力
输出的单位、符号约定、置信度指标或结果文件格式。结合体概率是模型输出，不是
结合观测。

## ByteFF

ByteFF 是数据驱动的分子力学力场。它推断分子的参数，并写出与 GROMACS 兼容的
ITP 文件。记录确立了推断和训练代码，也描述了训练阶段与基准数据。它未确立可
下载的预训练检查点，因此权重字段未核实。其仓库已归档，不再维护。README 引导
读者前往 ByteFF2 获取当前模型，并以单独条款提供托管 API 试用。服务访问不等于
读者可以自行运行的检查点。

README 声明 Apache-2.0 适用于仓库源码和附带的基准数据。论文和托管 API 分别
适用其他条款。记录描述了训练数据类型，但没有给出分子数量或化学空间清单，也没有
提供安装命令或可运行示例。只有先声明模拟方案，才能解释参数文件参与计算后得到
的任何结合自由能估计。

## ByteFF2

ByteFF2 是仍在维护的后继项目，发布了两个图神经网络力场。ByteFF-26 是使用
已命名的 THEMol 语料训练的非极化版本。ByteFF-Pol-25 是极化版本，记录称其用
高级量子化学数据训练，未经过实验校准。记录确立了推断代码和链接的 Hugging Face
仓库中的已发布权重，但未确立训练代码或数据配方。读者必须选择一种力场。记录
没有确立特定下游用途应该选哪一种。

记录中的 Apache-2.0 授权涵盖仓库源码及其发布的权重。THEMol、GROMACS 和
必需的补丁版 OpenMM 各自保留其条款。README 没有提供力场本身的安装命令。
运行该发布需要从源码构建补丁版 OpenMM 8.3.1 和 OpenMM-VelocityVerlet，
还需从源码构建 GROMACS 2025.3。这是一条构建路径，不能据此认定读者已执行
权重或算出亲和力。记录没有确立特定分子对的结合结果。

## 推演案例

读者有一条蛋白序列和一个配体，想知道两者是否结合。对每条路径，读者可以寻求
什么输出或资产、实际使用前需要取得什么，以及结论应在哪里止步？

AQAffinity 提供内部折叠的复合物和亲和力预测，但首先需要通过仓库访问门槛。
记录未能从无法读取的文件中确立可用检查点或输出约定。Nesso-1 根据序列和配体
输入给出亲和力数值与结合体概率。读者需要从页面找到其已发布权重，并在解释数值
之前核查输出约定和与机器环境相关的内核路径。这两种学习模型的输出都不能确立
化合物会结合。

ByteFF 提供分子参数和与 GROMACS 兼容的文件，而非直接判断是否结合。归档
仓库没有记录到可下载的检查点，API 试用属于单独的服务。ByteFF2 为可选择的
力场发布权重，但使用前需要完成所述源码构建并定义下游模拟方案。两种力场都可
作为计算的一部分，但两条记录都没有为这对分子提供模拟自由能或实测值。要声称
结合，读者还需要明确终点并取得独立的生物学证据。本案例没有生成任何结果。

## 独立练习

一位同事把权重字段的 `available` 当作每个已发布模型均可在本地运行的证明，
还把 ByteFF 的 API 试用称为可下载检查点。利用开放状态表及访问事实纠正这两项
说法。哪些路径的权重标为 `available`？为什么仍不能直接比较它们的亲和力数值？

<details data-worked-answer>
<summary>参考答案</summary>

Nesso-1 和 ByteFF2 的 `weights` 字段为 `available`。AQAffinity 和 ByteFF
的字段为 `unverified`。AQAffinity 有访问门槛，记录未能读取其文件。ByteFF
没有列出检查点，API 试用是托管服务。Nesso-1 没有给出检查点名称或下载命令，
ByteFF2 则需要从源码构建依赖并选择一种力场。更根本的区别是 Nesso-1 预测
亲和力数值，而 ByteFF2 提供模拟所需的参数。这些记录既未确立共同的输出定义，
也未确立匹配条件下的评估，因此不支持对亲和力数值直接排名。

</details>

## 适用范围

本课没有运行这四项资源，也没有预测亲和力。预测亲和力不是实测值，模拟自由能
也不是实测值，两者不能互换。记录无法读取 AQAffinity 的模型卡及文件，因此
不能靠推断填补其未核实字段。各资源及其其他组件有各自的许可条款，本课仅承载
记录对各项授权的解读。阅读开放状态字段不等于执行资产，也不能确立候选物的
结合、选择性或实验价值。
