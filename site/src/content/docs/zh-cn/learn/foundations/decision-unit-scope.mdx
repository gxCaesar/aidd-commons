## 学习目标与预备知识

完成本课后，你应能：

1. 说出把数据库行变成彼此独立的测量所需的三条规则，以及它们生效的顺序；
2. 读懂逐化合物普查表，并说清哪个计数回答哪个问题；
3. 说出每一条存活测量必须携带的七份语境；以及
4. 说出一个测量计数不能支撑哪些结论。

请先阅读[一个主张，一个决策单位](/zh-cn/learn/foundations/decision-unit/)。你应当
已经能把一个主张写成四个字段，并说出一个报告的指标是哪句话的证据。
[阅读来源并识别它描述的生物对象](/zh-cn/learn/foundations/source-and-entity-literacy/)
覆盖本课用到的实体与来源词汇。

**模式：在一个实时、带版本号的数据库发行版上做独立计算，同时有一份已提交的结果可读。**
推导案例中的数字读自本仓库已提交的本实验摘要，于 2026-10-21 针对 ChEMBL 37 计算。
末尾的命令从零重跑同一次计数，而协议在每次运行时都会重新断言实时发行版，因此后来的
发行版会让计数停下，而不是悄悄改变它。

## 一个报告值是一行

生物活性表按每个报告测量存储一行。这一行不是读者想要的那种测量。它是一份报告，
归档在某个实体名下，来自某一次实验，在某个检测里，出自某篇论文，针对某个靶点，在
某个生物体中，带着一个关系符号，并携带一项整理决定。论文里写下的一个数字变成表里的
一行，而这一行保留着那个数字之所以成立的全部语境。

由此得到两个结论，它们构成本课的全部内容。

第一，数据库为一个化合物返回的行数不是它证据规模的大小。它是有人就它写下了东西的
次数，包括写下组织严重度评分、ED50、体重的次数，也包括把同一个实验写了两遍的次数。

第二，两行可能是同一个实验被数了两次。一篇论文在两个检测里报告同一个终点会产生
两行。一篇论文把同一个检测报告两次会产生两行。某个化合物的盐型制剂会在第二个分子
标识符下产生行。

因此，测量计数既不是行计数减去什么，也不是行计数的改称。它是另一个量，由已声明的
规则产生，而这些规则必须先被声明出来，才能有人算出它。

## 读者可以核对的几个计数

三条规则把行变成测量，顺序很重要，因为每一条都改变着下一条看到的东西。

**实体规则确定单位。** 每一条活性行同时给出真正被测的形式和该行所归属的母体实体。
按形式计数，同一个化合物会被数两次，一次是游离碱，一次是它的盐。按母体计数则只数
一次。因此推断单位不是数据库标识符，而是一个已声明的实体，不点名它，读者就无法说清
`n` 计的是什么。

**准入规则确定什么才算数。** 只有当一行报告了已声明的终点、使用已声明的单位、带有
关系符号，并且 ChEMBL 自身的整理标记与质量标记放它过关时，它才被准入。排除理由按
已声明的顺序应用，匹配到的第一条理由就是该行的理由，因此这些理由把输入行恰好划分
开。这正是这个计数可审计的原因，读者可以追问哪些行被移除、为什么被移除，而不是拿到
一个总数。

**分组规则确定什么算同一次实验。** 两条被准入的点测量在共享一个检测、一篇文献和
一个终点类型时，是同一次测量，因为一次实验在一篇论文中报告一个终点就是一个数字。
在同一个检测内重复某次测量的行，是那一次测量的重复，不是它的额外证据。

上述数字背后的协议还声明了两个更便宜的计数，并把它们放在昂贵的那个之前，因为用错了
其中一个的比较，正是本课要防止的错误。

| 计数 | 它计的是什么 | 它错在哪里 |
| --- | --- | --- |
| 报告行数 | 数据库归档在该实体名下的每一条活性行 | 把非终点行、未整理行、界值和重复一并计入 |
| 不同检测数 | 该实体被测量过的检测个数 | 丢掉了文献，因此同一篇论文里被录入两次的一次检测只算一次，而一篇论文的两个检测算两次 |
| 独立测量数 | 被准入的点测量中不同检测、文献与终点键的个数 | 比较真正需要的量 |

对于一组解析出十个母体分子的十五个已声明 ChEMBL 分子，针对发布于 2026-05-01 的
ChEMBL 37，这三个计数读起来如下。

| 量 | 取值 |
| --- | ---: |
| 归档在这十个母体名下的活性行 | 13,305 |
| 被准入的点测量 | 488 |
| 被准入的界值 | 516 |
| 独立测量，分组单位（检测、文献、终点） | 486 |
| 独立实验，分组单位（检测、文献） | 484 |
| 在母体结构上报告的点测量 | 417 |
| 在盐型或混合物形式上报告的点测量 | 71 |

最后两行是实体规则的显形。488 次被准入的点测量中，有 71 次是在母体的盐型或混合物
形式上报告的，而不是在母体结构上，协议把它们计在母体上并单独报告。删掉它们会缩小
证据规模，而把它们当成独立化合物则会吹大候选集合，并且拿一个盐去和自己的游离碱
比较。

## 每一条存活测量带着什么

一条存活的测量是处在语境中的一行，而语境不是装饰。其中有七份会改变这个数字的含义。

| 语境字段 | 它告诉你什么 | VALPROIC ACID，27 次独立测量 |
| --- | --- | --- |
| 被测形式 | 检测里是哪一种物理形式 | 25 次在母体结构上，2 次在盐型 CHEMBL433 上 |
| 检测 | 产生这个数字的是哪一类实验 | 27 个不同检测，20 个结合、7 个功能 |
| 文献 | 是哪篇论文报告的 | 15 篇不同文献 |
| 靶点 | 化合物被测试针对什么 | 22 个不同靶点 |
| 生物体 | 检测用的是哪个生命系统 | 未记录 11，Homo sapiens 8，Rattus norvegicus 5，Bos taurus 3 |
| 置信分数 | ChEMBL 自己对检测的标记 | 8 出现在 11 次测量中，9 出现在 8 次，0 出现在 4 次，1 出现在 4 次 |
| 关系符号 | 这个数字是取值还是界值 | 这 27 次是 "="，125 条被准入界值全部是 ">" |

其中两份根本不在活性行上。ChEMBL 活性端点不携带检测生物体和置信分数，两者都必须
另行从检测记录中取回，而生物体未被记录的检测被报告为未记录，而不是被猜测。

关系符号这一份会悄悄改变算术。关系符号为 ">" 的行说的是值位于某个阈值的一侧，它
是一次真实测量，也是一个没用的数字，因为它无法与点值平均汇总。一个唯一存活证据是
大于 10,000 nM 的界值的化合物，压根没有被证明是强效的。

## 推导案例

队列中行数最多的化合物是丙戊酸。ChEMBL 在它的母体名下归档了 6,294 条活性行。在
本协议下它有 27 次独立测量，因此本实验自己的输出给出每次测量对应 233.1 行。

这些行按已声明的顺序消解，而这个顺序本身就是答案的一部分。2,349 行报告的东西在
已声明的纳摩尔效力家族之外，3,674 行从未被整理进 ChEMBL 的标准字段，99 行带有
数据有效性备注，10 行被标记为潜在重复，10 行没有关系符号。这留下 152 条被准入的行，
其中 125 条是界值，27 条是点测量，而 27 次点测量在检测、文献与终点这个键下归并为
27 次独立测量。

存活的证据也大多是负面的。125 条界值全部带 ">" 关系符号，其中 124 条把取值置于
10,000 nM 之上。6,294 这个
计数和 27 这个计数不是同一个问题的两个答案。前者是这个化合物被写下了多少次的次数。
后者是测量过它的独立实验有多少次，而只有后者能充当分母。

分组规则在第二个化合物上有可见的效果。普伐他汀有 1,594 条报告行和 37 次被准入的
点测量，它们在检测、文献与终点这个键下归并为 36 次独立测量，而在去掉终点类型后
归并为 34 次独立实验。这 34 次实验分布在 34 个不同检测中，取自 17 篇不同文献，涉及
14 个不同靶点。去掉终点类型，正是把同一次实验的两次测量变成一次的那个动作。

本实验的摘要里带着一个附有全部语境的报告值。值得完整读一遍，因为读者会据此写出的
那句话，比这一行短得多。

| 字段 | 取值 |
| --- | --- |
| 活性 | 495981 |
| 化合物 | VALPROIC ACID，母体 CHEMBL109 |
| 被测形式 | CHEMBL433，VALPROATE SODIUM，一个子实体盐型 |
| 终点 | IC50，89,000 nM，关系符号 "="，pChEMBL 4.05 |
| 检测 | CHEMBL646326，类型 B，置信分数 8，未记录检测生物体 |
| 文献 | CHEMBL1125615，J Med Chem，1991 |
| 靶点 | CHEMBL4049，aldo-keto reductase family 1 member A1，Sus scrofa |
| 检测场合标识符 | 该行上未记录 |

"丙戊酸有一个 89,000 nM 的 IC50"这句话保留了数字，丢掉了表中的每一个其他字段。被测的形式
是一个盐，而不是丙戊酸。那次检测完全没有记录生物体，所以这一行里没有任何东西说明
化合物是在哪个生命系统中被测试的。那篇论文来自 1991 年。靶点是猪的一种醛酮还原酶，
而这个值带着 4.05 的 pChEMBL，这是 ChEMBL 自己为这一行算出的值。

这些都不是关于丙戊酸的判断。它们是对一行的描述，而这一行才是证据的单位。

## 这些材料没有展示什么

测量的计数对效应的大小或质量什么也没说。这里没有任何内容支撑关于队列中某个化合物
是否强效、是否具选择性、是否安全或是否具备临床用途的主张，也没有在化合物之间做
任何比较。

队列是十五个为检验计数规则而挑选的分子。它不是 ChEMBL 的随机样本，在它上面算出的
任何比率都不估计总体量。488 次中的 71 次盐型测量是这十五个分子在 ChEMBL 37 中
碰巧是什么样子的计数，不是一个带抽样误差的比率，因此不报告不确定区间，也不应当
报告。

终点范围是一个已声明的纳摩尔效力家族，这里的测量计数是那个家族内部的计数。换一个
已声明的家族会给出不同的计数，协议自己的排除清单明说了这一点，而不是把它留在
言外。

分组规则是关于什么才算一次独立实验的判断。换一个判断会给出不同的计数。ChEMBL 自己
的模式文档指出，潜在重复标记为零并不保证一次测量是新颖的或独立的，这些材料只统计
标记所说的内容，不声称更多。

没有拟合任何东西，没有留出任何东西，也不预测任何东西，因此没有划分、没有拟合出的
参数、也没有留出评估可以报告。这些材料报告 ChEMBL 所存储的内容，而在 ChEMBL 把某个
盐型保留为它自己的母体、或把某个硫酸盐存成不含硫酸盐的形式的地方，它不纠正那条
记录。它报告存储的组分数和解析结果，把纠正留给读者。

## 独立练习

一位同事的笔记本为同一个化合物打印出两行，`n_records: 6,294` 和
`n_measurements: 27`，据此做成的幻灯片说这个化合物是队列中表征最充分的之一。

1. 说出按协议顺序解释这两个数字之间差异的规则。
2. 说清你会用两个数字中的哪一个作为关于这个化合物证据的主张的分母，并指出另一个
   数字会高估什么。
3. 27 次测量中有 2 次是在盐型 CHEMBL433 上测得的。说出使这些行不会在与母体行
   作比较时被当成来自不同化合物的那条规则，并指出如果只是把它们删掉，你会悄悄
   丢掉什么。

<details data-worked-answer>
<summary>参考答案</summary>

1. 实体规则排在最前，它也是问题里之所以只有一个化合物的原因。丙戊酸（CHEMBL109）
   和丙戊酸钠（CHEMBL433）是同一个母体分子的两条 ChEMBL 记录，因此计数保留在母体
   上。准入规则接着把 6,294 行降到 152 行，移除 2,349 行终点家族之外的行、3,674 行
   从未被整理进 ChEMBL 标准字段的行、99 行带数据有效性备注的行、10 个潜在重复和
   10 行没有关系符号的行。分组规则随后把这 152 行拆成 125 条界值和 27 次点测量，
   而 27 次点测量在检测、文献与终点这个键下归并为 27 次独立测量。这两条规则合起来
   解释了全部差距。
2. 独立测量数，也就是 27，因为关于某个化合物证据的主张需要独立实验，而来自同一个
   检测和同一篇论文的重复不是独立证据。6,294 这个行数会把该化合物的证据规模高估
   两个数量级以上，而且它会把 2,349 行根本不是效力的内容也当作证据计入。与 27 次
   点测量同时被准入的 125 条界值让这一点更尖锐，因为其中 124 条把取值置于 10,000 nM
   之上，那是效力不存在的证据，而不是效力存在的证据。
3. 这条规则是准入子实体行、把它计在母体上、并把它单独报告为盐型测量，协议正是这样
   做的，而它的姊妹实验明确不这样做。删掉那 2 条盐型行会把计数从 27 降到 25，并
   悄悄丢掉该化合物的一部分证据。把盐和母体当成两个化合物则更糟，因为跨这两条记录
   的比较会把一个制剂效应读成分子之间的差异。

</details>

## 亲自跑这个计数

[决策单元尺度实验](/zh-cn/labs/decision-unit-scope/)是本课的可运行形式。它打印实体
解析、准入漏斗、逐化合物普查和具名例子，并对着缓存重新核对每一个已公布的计数。

从仓库根目录开始：

```bash
uv sync --group dev
uv run python labs/decision_unit_scope/run_lab.py download
uv run python labs/decision_unit_scope/inspect_decision_unit_scope.py show
uv run python labs/decision_unit_scope/inspect_decision_unit_scope.py check
```

下载发起 41 个 HTTP 请求，把十三件产物写入 `.cache/decision_unit_scope/` 下被 git
忽略的缓存。`check` 命令在没有网络、没有缓存的情况下也能运行。本实验冷启动约需五
分钟，热缓存只需数秒，而且没有任何命令会写出拟合出的模型或锁定的结果。

接下来可阅读[三个实验中的数据划分与泄漏](/zh-cn/learn/evaluation-and-reproducibility/split-and-leakage-cases/)
了解实体之外的推断单位，以及[从测定记录到建模表](/zh-cn/learn/data-governance/records-to-model-table/)
了解存活的行如何变成一张可以拟合模型的表。
