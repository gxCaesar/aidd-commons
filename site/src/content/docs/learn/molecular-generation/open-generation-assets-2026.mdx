## Learning goals and prerequisites

After [Generative model mechanisms](/learn/molecular-generation/generative-model-mechanisms/)
and [Choosing generation tools and evaluation tasks](/learn/molecular-generation/generation-resource-guide/),
identify which model assets a reader can obtain, which terms apply to each
asset, and what the named training data do not explain. This is a reading
lesson with a written exercise. It does not run either generator.

## Comparison contract

Zatom-1 and MolCraftDiffusion both address three-dimensional generation, but
their catalogue records establish different routes to using their assets. A
published checkpoint listing does not by itself establish access, and a code
licence does not supply terms for weights or training corpora. Compare what the
records establish for each asset, then keep the resulting coordinate proposals
separate from claims about physical plausibility or drug utility.

## Zatom-1

Zatom-1 is a multimodal flow-matching model for three-dimensional molecules
and materials. It was built to share a pretrained model across generation and
property-prediction tasks. Its repository publishes inference, training, and
evaluation code, which a reader can inspect for those operations. A Zenodo
record supplies the full checkpoint release and generated sample archives.
The README also gives a script to fetch the named training corpora. These are
routes to assets, not evidence that the lesson ran a model or reproduced its
training.

The repository's code uses a modified BSD-3-Clause licence with an added clause
granting the University a licence to enhancements contributors make available.
The Zenodo record places the checkpoints and generated samples under CC BY 4.0.
Redistributing source
and redistributing a checkpoint therefore involve different grants. The
training datasets have their own terms, which this record does not establish.
The README names QM9, MP20, GEOM-Drugs, QMOF150, OMol25, Matbench and MPtrj,
but gives no filtering, splitting or curation procedure for them. It also
lists checkpoint variants without choosing one for a downstream use. Neither
the training recipe nor the physical validity of the archived coordinates is
established.

## MolCraftDiffusion

MolCraftDiffusion is a modular platform for three-dimensional molecular
generation in Cartesian space. It brings de novo, property-directed,
pocket-conditioned and other generation approaches under a shared command
line, configuration system, data pipeline and checkpoint system. Its repository
documents inference, training and evaluation code. A reader can inspect those
interfaces, but the README says the asset catalogue repositories are currently
private and require a Hugging Face token with permission. It describes archived
datasets, checkpoints and example configurations without establishing that a
reader can obtain them.

The README states no licence for the code. Its only licence-bearing line is in
the article's BibTeX metadata and applies to the article, not the software.
The record establishes no licence for the weights or datasets either. It names
no individual chemical dataset or train and validation split, so the corpus
behind any released checkpoint cannot be identified from the page. The number
of published checkpoints is also unstated. Available training code does not
fill those gaps.

## Worked case

A reader wants to run one of these releases. From the records, what must the
reader obtain, what licence covers each obtained artefact, and which part of
the pipeline does that licence address? What remains to check before a claim
about a trained model or its output is warranted?

For Zatom-1, the source repository supplies code for inference, training and
evaluation under the modified BSD-3-Clause terms. The reader would select and
obtain a checkpoint from Zenodo for inference. That checkpoint, and any
generated sample archive taken from the record, carries CC BY 4.0 rather than
the code grant. The download script supplies a route to the named corpora, but
their separate terms and the missing filtering and splitting decisions still
need checking for a training reproduction. For MolCraftDiffusion, the reader
can inspect the code and command line, but obtaining the stated checkpoints,
datasets and runnable configurations requires a token with permission. The
record establishes no software or asset licence for those steps. The article's
metadata licence cannot fill that gap. Neither route establishes that a
generated structure is physically possible or useful as a drug.

## Scope

Neither model was run here and no sample was generated. A generated structure
is a proposal, and a sample archive is a set of coordinates. The records do
not establish that those coordinates are physically possible or that any
compound is a drug. Neither record establishes a training recipe. This lesson
names Zatom-1's corpora where the record names them without characterising
their construction, and it leaves MolCraftDiffusion's unnamed corpora unknown.
The resources retain their own licences, and only the records' readings of
their scopes are carried here. Reading an openness cell does not execute an
asset.
