## Learning goals and prerequisites

After [Protein, complex, cell-state and knowledge-graph representations](/learn/representations/complex-cell-and-knowledge-graphs/), use this dated reading to decide what 10 catalogue records about single-cell foundation models and virtual cells establish. The earlier lesson taught how a cell state is encoded and what such an encoding discards. This reading moves one step up the stack, to the models that learn an embedding of a cell state at scale and the ones that claim to predict what a perturbation does to it.

After this lesson, you should be able to:

1. state the input and output contract of a cell representation and of a perturbation outcome prediction, and name what separates them;
2. read the seven openness dimensions for each record without merging them into a single openness label;
3. match a licence to the asset it covers, when the code and the weights carry different terms;
4. distinguish evidence for organised biological features from evidence for regulatory responses, and say which evidence in this family stops a broader conclusion or remains absent.

This is a source reading with a written exercise. No method in this family was run, reproduced, or re-implemented for this lesson, no checkpoint was loaded, and no dataset was downloaded. The records carry no matched comparison across the family, so this reading supports no ranking.

## Two task contracts

The first contract takes one cell as input and returns a vector. The input is an expression profile for that cell under a declared measurement and preprocessing pipeline. The output is an embedding in a shared latent space, and in several records a second embedding for the measured genes. The useful property is transfer. Cells from a tissue, an assay, or a species that the corpus never contained can still be placed in the same space, because the encoder needs no label, no retraining, and no fine-tuning to produce coordinates. [UCE](https://github.com/snap-stanford/UCE) states this property in the strongest form, mapping new cells from new tissues and new species into one latent space. Nothing in this contract predicts an outcome. The embedding says where a cell sits relative to other cells, and the axes are learned from correlation rather than from an intervention.

The second contract takes an intervention as input and returns a counterfactual. The input is a baseline cell state, a declared perturbation such as a gene, a gene set, or a compound, and a context such as cell type, dose, or condition. The output is a predicted post-perturbation expression profile, or a change relative to a control. The useful property is a counterfactual that a measured screen can contradict.

The gap between the two contracts is the point of this reading. A representation of a cell is not a prediction about an intervention, and a model that embeds cells well gives no evidence that it can predict what a drug does. The records in this family establish the first contract much better than the second. Two further distinctions keep the reading honest. A catalogue task label such as cell-context-inspection or out-of-distribution-evaluation classifies what a project claims to cover. It is not a measured result, and it carries no metric, split, or evaluation set. A model name is not a capability. What an artefact is for, and where its evidence stops, has to be read from the record.

Tahoe-x1 adds a pretraining-scale claim without a numerical benchmark result in its record. The feature atlases add a test of what learned representations hold: organised features do not establish that a model represents regulatory responses. Their CRISPRi result has to be read alongside the feature maps.

## scGPT

The [scGPT repository](https://github.com/bowang-lab/scGPT) describes a generative pretrained transformer for single-cell multi-omics that embeds gene expression into cell and gene representations, and the record lists cell annotation, batch integration, regulatory-network inference, and perturbation-effect prediction among its uses. The [README](https://raw.githubusercontent.com/bowang-lab/scGPT/main/README.md) points to a pretrained model zoo covering whole-human, brain, blood, heart, lung, kidney, pan-cancer, and continual pretrained checkpoints hosted on Google Drive. The architecture evidence is the preprint record, [bioRxiv DOI 10.1101/2023.04.30.538439](https://doi.org/10.1101/2023.04.30.538439), and the journal version, [Nature Methods 21(8):1470-1480 (2024)](https://pubmed.ncbi.nlm.nih.gov/38409223/). The record states no objective, no training schedule, and no metric that a reader could audit.

Inference code, weights, and architecture are marked available. Training code, the data recipe, training data, and evaluation code are unverified, and the README itself lists the pretraining code as an open item and describes a separate integrate-huggingface-model branch as preliminary support for the pretraining workflow, so the release state of the training code is not settled by the opened pages. The [MIT licence file](https://raw.githubusercontent.com/bowang-lab/scGPT/main/LICENSE) covers the repository source and reads "Copyright (c) 2022 suber", a holder and year that do not match the scGPT authors, and the README states no separate terms for the Google Drive checkpoints. The model zoo lists cell counts per population and the paper abstract reports a corpus of more than 33 million cells, but no named public corpus is identified as the pretraining data. CellxGene appears in the README only as a source for a reference-mapping feature. The scale figure therefore bounds the corpus size without fixing which cells were in it.

## scFoundation

The [scFoundation repository](https://github.com/biomap-research/scFoundation) describes an asymmetric transformer pretrained on more than 50 million human single-cell transcriptomes that produces cell and gene embeddings for cell-type annotation, drug-response prediction, and perturbation prediction. The [README](https://raw.githubusercontent.com/biomap-research/scFoundation/main/README.md) ships DataSupplement1.xlsx and DataSupplement2.xlsx with the collection workflow, which is why the record marks the data recipe available, and the architecture evidence is [Nature Methods DOI 10.1038/s41592-024-02305-7](https://doi.org/10.1038/s41592-024-02305-7). The README does not name the source datasets, so the corpus composition is not verifiable from the opened pages. The record also states that the README runs GEARS for perturbation prediction, with the status of that relation unverified.

Inference code, weights, architecture, and the data recipe are marked available, while training code, training data, and evaluation code are unverified. Access is research only, and the record explains why in two licences rather than one. The repository source is Apache-2.0, and the [model licence file](https://raw.githubusercontent.com/biomap-research/scFoundation/main/MODEL_LICENSE) governs the weights alone, granting use solely for non-commercial research purposes and prohibiting use, copying, modification, publication, distribution, reproduction, or derivative works of the parameters for any commercial, military, or illegal purpose under the laws of the People's Republic of China. A reader who takes the Apache-2.0 terms to the weights has taken the wrong licence. The online inference and command-line tooling at [aigp.biomap.com](https://aigp.biomap.com/) carries no stated terms in the opened pages.

## CellFM

The [CellFM repository](https://github.com/biomed-AI/CellFM) describes a RetNet-based foundation model pretrained on transcriptomics of about 100 million human cells, applied to cell annotation, perturbation prediction, gene-function prediction, batch correction, and cell-type-specific lncRNA identification. The [model card](https://huggingface.co/ShangguanNingyuan/CellFM) reports 19,914 samples holding 102,304,686 human cells, and the [Zenodo record](https://zenodo.org/records/15138665) holds the CellFM_data.zip archive of the datasets used in CellFM, about 5.3 GB. The architecture evidence is [Nature Communications 16:4679 (2025)](https://doi.org/10.1038/s41467-025-59926-5). This is the only record in the family that names a data archive, and neither the archive description nor the model card enumerates the source atlases or the per-sample provenance of those samples.

CellFM's training code is marked available on the README's evidence, with inference code, weights, architecture, and training data available as well. The data recipe and evaluation code remain unverified. Its terms are split in a way that changes what a reader may do. The repository source and the model card carry CC-BY-NC-ND-4.0, which grants reproduction and sharing of the licensed material for non-commercial purposes, allows adapted material to be produced and reproduced for non-commercial purposes, and forbids sharing that adapted material. A fine-tuned derivative may therefore exist inside a group and may not be published. The [Zenodo archive](https://zenodo.org/records/15138665) is separately CC-BY-4.0, and the [licence file](https://raw.githubusercontent.com/biomed-AI/CellFM/main/LICENSE-cc-by-nc-nd-4.0) is named for its non-commercial, no-derivatives grant. The data terms and the model terms do not match, and a licence that names the archive says nothing about the code that reads it.

## UCE

The [UCE repository](https://github.com/snap-stanford/UCE) describes a self-supervised model that maps single-cell transcriptomes into one shared biological latent space, so that new cells from new tissues and new species can be embedded without labels, retraining, or fine-tuning. The [Nature record](https://doi.org/10.1038/s41586-026-10689-z) reports an Integrated Mega-scale Atlas of 36 million cells and more than 1,000 named cell types as a product of the model, and the record notes that the abstract does not state that this atlas is the training set. The [README](https://raw.githubusercontent.com/snap-stanford/UCE/main/README.md) points to 33-layer model files on [Figshare article 24320806](https://figshare.com/articles/dataset/Universal_Cell_Embedding_Model_Files/24320806) and states that the evaluation scripts download four-layer model files automatically without giving their location.

Inference code, weights, and architecture are marked available, and training code, the data recipe, training data, and evaluation code are unverified. The [MIT licence file](https://raw.githubusercontent.com/snap-stanford/UCE/main/LICENSE) covers the repository source and reads "Copyright (c) 2023 Yanay Rosen, Yusuf Roohani, Jure Leskovec". No terms are stated for the 33-layer weights on Figshare or for the prepared datasets, and the Figshare record returned HTTP 403 when it was opened on 2026-10-21, so the terms of the released weights were never read. The four-layer checkpoint that the evaluation scripts fetch has no stated provenance either. Nothing in this record fixes the composition of the pretraining corpus, and the atlas of named cell types is a product of the model rather than a documented input to it.

## Tahoe-x1

The [Tahoe-x1 repository](https://github.com/tahoebio/tahoe-x1) describes a family of perturbation-trained single-cell foundation models from 70 million to 3 billion parameters, with published weights and adaptation to cancer-focused downstream tasks. Its [README](https://raw.githubusercontent.com/tahoebio/tahoe-x1/main/README.md) gives a headline pretraining size of about 266 million single-cell profiles, while its 6 rows for unfiltered and filtered versions of CellxGene 2025-01, scBaseCamp 2025-02 and Tahoe-100M sum to about 269 million. The record preserves both figures because the page does not reconcile them. The filtered corpora discard cells with the fewest detected genes, which the page says can affect cohort selection. Stage 2 of pretraining therefore uses a different population from stage 1. The page describes 2-stage pretraining and downstream adaptation but gives no formal pretraining objective, loss or masking procedure.

The record names evaluations of DepMap essentiality, MSigDB hallmarks, cell-type classification across 5 tissues, and perturbation prediction in unseen contexts, but carries no numerical benchmark result or matched comparison. Its [bioRxiv preprint](https://www.biorxiv.org/content/10.1101/2025.10.23.683759v1) is a source for the model, not a numerical result supplied by this record. The current codebase supports only flash attention with the attention mask disabled; the Triton backend and custom attention masks used to train the 2 smaller models are no longer supported. The released inference path is therefore not the training path for those models.

Inference code, training code, weights, architecture, data recipe and training data are marked available; evaluation code is unverified. The repository's Apache-2.0 marker covers its source and published checkpoints. Some training corpora are not publicly downloadable and require an access request, so obtaining the weights does not give a reader every corpus behind them. Corpus licences remain the licences of the corpora themselves. Pretraining scale and released weights establish neither cell-type coverage nor measured perturbation-prediction performance.

## Sparse-autoencoder feature atlases for scGPT and Geneformer

The [feature-atlas preprint](https://arxiv.org/abs/2603.02952) describes interactive atlases of sparse-autoencoder features extracted from every layer of scGPT and Geneformer, with separate [scGPT](https://github.com/biodyn-ai/scgpt-atlas) and [Geneformer](https://github.com/biodyn-ai/geneformer-atlas) web-application repositories. Its title reports organised biological knowledge but minimal regulatory logic. Under genome-scale CRISPRi testing, only 3 of 48 transcription factors, or 6.2%, showed transcription-factor-specific feature responses. A multi-tissue control raised this to 10.4%, or 5 of 48. A representation that separates cell types is therefore not by itself evidence that the model represents regulation.

The paper also reports atlases of 82,525 and 24,527 features, 99.8% of features invisible to singular value decomposition, and 29–59% of features annotating to a named pathway database among Gene Ontology, KEGG, Reactome, STRING and TRRUST. It reports 141 and 76 co-activation modules, a median causal specificity of 2.36 times, and cross-layer information highways spanning 63–99.8%. The catalogue record takes these figures from the preprint abstract and summary, rather than from a full-text reanalysis. The CRISPRi result is the limit to carry forward, rather than treating atlas size as a capability result.

The paper is an arXiv preprint submitted on 2026-03-03, with no journal or conference venue listed. The record marks inference code available and the other 6 openness dimensions unverified; its access level is also unverified, and it lists no licence. Both repositories are web-application source trees without a README or licence file, so readers reach the atlases through hosted pages rather than a published package. They contain the application source, not the extracted features, trained sparse autoencoders, annotation tables or layer-by-layer results. The repositories alone therefore cannot recompute the atlases.

## GEARS

The [GEARS repository](https://github.com/snap-stanford/GEARS) describes a graph-based deep learning model that predicts the transcriptional response to single-gene and multi-gene perturbations by combining a gene embedding with a knowledge graph of gene-gene relationships. That is the second contract, and the knowledge graph is the input structure that carries it, so the quality of the graph bounds the prediction. The [README](https://raw.githubusercontent.com/snap-stanford/GEARS/master/README.md) names Norman et al. 2019 as the training set of the linked model, and the [dataset loader](https://raw.githubusercontent.com/snap-stanford/GEARS/master/gears/pertdata.py) downloads the norman, adamson, and dixit processed archives from public Harvard Dataverse endpoints. The architecture evidence is [Nature Biotechnology 42(6):927-935 (2024)](https://doi.org/10.1038/s41587-023-01905-6). The README states no dataset versions, no splits, and no further pretraining corpus, and the record carries no metric table, so no headroom and no matched comparison can be read from it.

Training data is marked available, and inference code and evaluation code are available, while training code, weights, and the data recipe are unverified. Weights are the notable absence. The README gives no download location for a pretrained model, and the only route to the trained Norman model it names is a Colab notebook that requires Colab Pro, so the availability of released weights is unverified. The [MIT licence file](https://raw.githubusercontent.com/snap-stanford/GEARS/master/LICENSE) covers the repository source and reads "Copyright (c) 2022 Yusuf Roohani, Kexin Huang, Jure Leskovec", the README carries no licence section, and no terms are stated for the trained model or for the datasets the package loads. The catalogue also tags this record with the task benchmark-evaluation, which names an activity rather than a measured outcome.

## CPA

The [CPA repository](https://github.com/theislab/cpa) describes a compositional perturbation autoencoder that factorises single-cell transcriptional responses into basal, drug, and perturbation effects, so that dose, cell-type, and genetic interventions can be extrapolated to unseen combinations. The [Molecular Systems Biology 19(6):e11517 (2023)](https://doi.org/10.15252/msb.202211517) record reports that the genetic screen used a Perturb-seq experiment and that newly generated combination data were used, without naming the datasets or giving splits. The [README](https://raw.githubusercontent.com/theislab/cpa/main/README.md) names its tutorials through the link labels combosciplex, Norman, and Kang, but it does not state which dataset any released checkpoint was trained on.

Inference code, weights, and architecture are marked available, and training code, the data recipe, training data, and evaluation code are unverified. The [BSD-3-Clause licence file](https://raw.githubusercontent.com/theislab/cpa/main/LICENSE) covers the repository source and reads "Copyright (c) 2023, Mohammad Lotfollahi, Theislab". The README has no licence section, and no terms are stated for the pre-trained models or the datasets that sit in the same [Google Drive collection](https://drive.google.com/drive/folders/1yFB0gBr72_KLLp1asojxTgTqgz6cwpju?usp=drive_link). A released checkpoint and a released dataset are therefore assets whose terms a reader must obtain from the collection rather than from the licence file. The record's task classification includes cell-context-inspection and out-of-distribution-evaluation, which describes what the project claims to cover rather than a measured generalization result.

## PertFormer

The [PertFormer repository](https://github.com/alibaba/damo-pertformer) describes a multimodal transformer with 3 billion parameters that predicts the effects of genetic, transcriptional, and sequence perturbations on gene expression and cell fate from unperturbed sequence, and that nominates perturbation targets. The [preprint record](https://doi.org/10.1101/2024.12.19.629561) gives only modality counts, namely nine data types, 55 billion base pairs of bulk data, and 1.5 billion paired multi-omic observations from one million cells, and it names no benchmark datasets, no splits, and no metrics. The [model card](https://huggingface.co/GenomicIntelligenceDamoAcademy/pertformer) hosts the checkpoints, about 13 GB.

Inference code, weights, and architecture are marked available, and training code, the data recipe, training data, and evaluation code are unverified. Access is research only. The repository source and the model card carry CC-BY-NC-ND-4.0, and the [licence file](https://raw.githubusercontent.com/alibaba/damo-pertformer/main/LICENSE) states no model-weight or data-specific term, so the terms for the checkpoints are the terms of the source and the card rather than of a separate weight licence. Neither the README, the model card, nor the abstract names the pretraining corpora. The record also notes a title mismatch. The README names the manuscript "PertFormer: Zero-shot perturbation prediction and target discovery from wild-type biology" and states that the manuscript was under review, while the bioRxiv record at the cited DOI carries the title "Multimodal foundation model predicts zero-shot functional perturbations and cell fate dynamics". A reader who cites the model must pick one title and record the discrepancy.

## The zero-shot evaluation study

The [zero-shot evaluation repository](https://github.com/microsoft/zero-shot-scfoundation) is a benchmark rather than a model, and it uses a matched protocol for its representation endpoints. Its [README](https://raw.githubusercontent.com/microsoft/zero-shot-scfoundation/main/README.md) names two tasks, cell type clustering and batch integration, and two baselines, scVI and a highly variable gene heuristic, and it evaluates scGPT and Geneformer against them using released notebooks and a released data archive. The [preprint record](https://doi.org/10.1101/2023.10.16.561085) reports limited reliability in zero-shot settings and names no baselines, no datasets, no splits, and no metrics, so the released notebooks are the only place where the baseline implementations are shown.

Inference code and evaluation code are marked available, and training code, weights, and architecture are not applicable, which is the correct classification for a study that trains nothing. The data recipe is unverified and the README does not name the individual datasets inside the [Figshare archive](https://doi.org/10.6084/m9.figshare.24747228), so the composition of the evaluation set is not verifiable from the opened pages. The [MIT licence file](https://raw.githubusercontent.com/microsoft/zero-shot-scfoundation/main/LICENSE) covers this repository's notebooks and reads "Copyright (c) Microsoft Corporation." with no year given, and the weights it loads come from the scGPT and Geneformer repositories, whose own terms apply to them. The notebooks evaluate other people's checkpoints under one protocol for these endpoints, although the record carries no metric values.

## Training corpora and cell-type coverage

Two related sequence-model records sharpen this boundary. [tGPT](https://github.com/deeplearningplus/tGPT) is an autoregressive GPT model that treats within-cell gene-expression ranking as a generative pretraining task and produces cell-level features for single-cell and bulk-tissue analysis. Its README and [paper abstract](https://doi.org/10.1101/2022.01.31.478596) give a scale of 22.3 million single-cell transcriptomes without naming a source corpus, so training data remains unverified. The pretrained tokenizer and checkpoint are loaded from a [model card](https://huggingface.co/lixiangchun/transcriptome-gpt-1024-8-16-64) with no stated licence, and the repository's GPL 3.0 terms come from its [LICENSE file](https://raw.githubusercontent.com/deeplearningplus/tGPT/main/LICENSE), not from a README licence section or the weight card. [Geneformer](https://github.com/jkobject/geneformer), already named in this reading, has a different asset boundary. Its repository displayed no licence and its LICENSE path returned HTTP 404 when checked on 2026-10-21, while Apache 2.0 appears on the linked [model card](https://huggingface.co/ctheodoris/Geneformer) and is not shown to cover repository source code.

5 model records leave the training corpus unverified: scGPT, scFoundation, UCE, CPA, and PertFormer. CellFM names an archive without enumerating its source atlases, and GEARS names Norman et al. 2019 as the training set of one linked model without giving versions or splits. Tahoe-x1 names pretraining corpora, but some require an access request, and filtering changes which cells enter the second stage. The zero-shot study trains nothing, so the dimension does not apply. The feature atlases inspect scGPT and Geneformer representations, but their application repositories do not contain the extracted features or layer-by-layer results and do not resolve scGPT's missing corpus composition.

The scale figures in these records are easy to read as coverage guarantees, and they are not. The scGPT abstract reports more than 33 million cells. The scFoundation README gives more than 50 million human single-cell transcriptomes. The CellFM model card reports 19,914 samples holding 102,304,686 human cells, and the README gives a pretraining scale of about 100 million human cells. The UCE paper reports an atlas of 36 million cells and more than 1,000 named cell types as a product of the model. The PertFormer abstract gives nine data types, 55 billion base pairs of bulk data, and 1.5 billion paired multi-omic observations from one million cells. For these records, each figure bounds a quantity but is not a cell-type inventory that can be checked against a named pretraining corpus. Tahoe-x1 names corpora, yet its headline of about 266 million profiles and the approximately 269 million summed from its 6 rows remain unreconciled, and access requests and filtering limit what a reader can check about cell-type coverage.

That is the practical consequence a reader must carry. A model cannot be assumed to cover a cell type that its corpus never contained, and these records alone do not let a reader determine whether a given cell type was in the relevant training population. For scGPT the model zoo names populations such as whole-human and pan-cancer, which are checkpoint labels, not documented training sets, since the record states that no named public corpus is identified as the pretraining data. A predictor that has never seen a cell type can still return a confident expression profile for it, and the confidence is not evidence of coverage.

## Worked case

A team plans to use CPA to predict the transcriptional response to a compound in primary human hepatocytes, and plans to feed it scFoundation gene embeddings. The team cites the CPA record's task classification, which includes cell-context-inspection and out-of-distribution-evaluation, and reads the scFoundation scale figure of more than 50 million human single-cell transcriptomes as evidence that hepatocytes are covered. The audit has four steps.

1. The task label. A catalogue task field classifies what the project claims to cover. It is not a measured out-of-distribution result, and the CPA record carries no metric, no split, and no named evaluation dataset.
2. The corpus. The scFoundation README does not name its source datasets, so the figure bounds corpus size and not corpus composition. Nothing in either record states that hepatocytes are present. The team would need a per-cell-type count from the actual training corpus, which the records do not carry.
3. The licence. The CPA code is BSD-3-Clause, while the pre-trained models and datasets in the Google Drive collection carry no stated per-file terms. The scFoundation code is Apache-2.0 and the scFoundation weights are non-commercial research only, so the gene embeddings the team wants to reuse are the restricted asset rather than the code.
4. The comparison. To claim that CPA predicts the compound's effect, the team needs a measured screen, a declared held-out set, a metric, and a baseline under the same protocol. No record in this family carries those four for perturbation prediction.

What the team can state today is narrow. These artefacts exist, their licences are these, their corpora are unverified, and no record in this family measures this prediction. That is a source description, and it is the correct deliverable for a reading.

The feature atlases sharpen the question without supplying the team's missing result. Their CRISPRi finding concerns scGPT and Geneformer, so it cannot be transferred as a measured result for CPA or scFoundation. It does show why a cell embedding cannot stand in for evidence of regulatory response.

The coverage claim skips the inventory of the corpus. The model zoo lists checkpoint populations and cell counts per population, but the record states that no named public corpus is identified as the pretraining data, so a checkpoint label is not a training-set inventory. ## Scope and what the material does not show

The 10 records establish asset, licence, and task statements: the original 8 were reviewed on 2026-10-21, and the Tahoe-x1 and feature-atlas records on 2026-10-23. They do not establish an executed common benchmark, a reproduced model, a measured perturbation prediction for the worked case, an unrestricted reuse of every linked asset, or reader learning outcomes. 5 model records leave the training corpus unverified, which prevents a broad claim about cell-type coverage; Tahoe-x1 names corpora but has access and filtering limits and no numerical benchmark result in its record. The feature atlases report a limited regulatory response under CRISPRi. That result comes from a preprint, and the application repositories cannot reproduce the atlas. The zero-shot evaluation study's matched protocol carries no metric values in the record and does not name the datasets inside its own archive. The models here were not run for this lesson.
