## Foundations

Structure prediction, pocket identification, and co-folding are related but
different tasks. A predicted complex can support a structural hypothesis; it
does not by itself establish binding, selectivity, cellular activity, or a
therapeutic mechanism. The objects, input state, and intended experimental
decision need to be recorded before interpreting an output.

## Practical workflow

Start with the experimentally known sequence, construct, ligand state, and
assay context. Inspect whether the selected system actually releases the
inference code, weights, training material, and evaluation material needed for
the intended use. The [open co-folding frontier Atlas](/atlas/open-cofolding-frontier/)
keeps those dimensions separate rather than treating a repository as a blanket
openness claim.

## Evaluation

Use a held-out structural or biochemical question matched to the decision, and
check physical plausibility, alternative states, calibration, and overlap with
training-like examples when that information is available. Confirm a
decision-relevant prediction with an assay, structure, or perturbation rather
than a model score alone.

Before comparing systems, separate the claims. A monomer prediction, a complex
prediction, a co-folded pose, a docked pose and an experimental binding
measurement are five different things that arrive in the same file format, and
the [claim separation lab](/labs/cofolding-claim-separation/) prints which one
each registered system actually supports, in one offline command.

## Frontier and open questions

[AlphaFold 3](https://www.nature.com/articles/s41586-024-07487-w),
[Chai-1](https://github.com/chaidiscovery/chai-lab),
[Boltz](https://github.com/jwohlwend/boltz),
[OpenFold](https://github.com/aqlaboratory/openfold), and
[Protenix](https://github.com/bytedance/Protenix) expose different combinations
of assets and documentation. Reported accuracy is therefore not a substitute
for an asset-level reproducibility audit.

## OpenFold3 and OpenBind-0: package, parameters and cutoff

The original OpenFold above implements the AlphaFold2 family. The distinct [OpenFold3 repository](https://github.com/aqlaboratory/openfold-3) predicts biomolecular structures and remains a research preview, with final-model work ongoing. Its [parameter reference](https://openfold-3.readthedocs.io/en/latest/parameters_reference.html), checked on 2026-10-25, makes a package update scientifically consequential:

| Resource or parameter set | Package contract | Training-date boundary |
| --- | --- | --- |
| Original OpenFold | Separate `aqlaboratory/openfold` repository | Do not inherit an OpenFold3 cutoff |
| OpenFold3 preview2 | Requires a compatible version below `0.5.0` | Identify that preview's own parameter set |
| OpenFold3 with OpenBind-0 | Default from `0.5.0`; `openbind-2025-06-30-174k`, file `of3-ob-2025-06-30-174k.pt` | PDB training cutoff `2025-06-30` |

The [OpenBind-0 release analysis](https://openbind.uk/news/blog-openbind-0-advancing-open-molecular-structure-prediction/), dated 2026-08-21, describes public code, weights and training recipes under Apache 2.0. The opened [code licence](https://github.com/aqlaboratory/openfold-3/blob/main/LICENSE) confirms the repository grant. The complete training-corpus inventory and asset-level terms were not checked end to end, and linked benchmark scripts were not inspected, so the catalogue leaves training data and evaluation code unverified. The training cutoff is distinct from the release date.

Inference-time chemical steering is another protocol choice: it changes ligand geometry without being a new training cutoff. The release analysis preserves target-dependent failures, including difficult flexible ligands and pocket changes; newer training and fragment fine-tuning did not uniformly repair them. Comparisons span different cutoffs and target regimes and establish no universal ranking. A chemically valid predicted pose still does not establish affinity. The [affinity routes lesson](/learn/structure-and-pockets/affinity-routes-2026/) distinguishes a structure trunk from an affinity head.

### Constructed version exercise

A report records only “OpenFold3 default.” Its author used a preview2-compatible package, while a reader installs `0.5.0` and accepts its default parameters. Do identical sequences and ligands make these the same model comparison? Which additional fields belong in the report?

<details data-worked-answer>
<summary>Worked answer</summary>

No. The package changed the default parameter set, and the older preview parameters also have a compatibility boundary. Record the package version, named checkpoint and file, checkpoint-specific training cutoff, input preparation and chemical-steering settings before interpreting a difference. Hold the evaluation population and metrics fixed for a controlled comparison. Neither a different pose nor an improved geometric metric supplies an affinity measurement. This exercise runs neither configuration.

</details>

## What v0.1 does not yet teach

v0.1 does not make a universal ranking of co-folding systems, offer a
prospective validation dataset, or infer availability where primary evidence
does not state it.
